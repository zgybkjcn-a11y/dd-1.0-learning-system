# DD-1.0 自动开发 Goal 提示词

版本：GP-1.0；日期：2026-11-02。  
用途：在支持持续目标执行的编码客户端中，启动本项目 V1 开发。  
当前状态：**仅生成提示词，未启动 Goal、开发服务、模型调用或部署。**

## 使用方法

1. 在项目根目录打开编码客户端。
2. 将下一节“主提示词”完整交给客户端，并使用该客户端实际提供的 Goal/持续目标入口。本文不假定某个版本一定支持特定斜杠命令；没有 Goal 工具时可按普通持续开发任务执行，但不能声称目标已在后台自动续跑。
3. 也可以直接发送文末“简短启动指令”，让执行者从本文件读取完整要求。

默认目标是 DD-1.0 的 **V1 完整技术交付和隔离验收**：落实必需范围，准备真实试用所需的代码、部署物和验证证据。T23 的真实持续试用、学科人工裁决及正式环境切换需要真实条件，不能由模型虚构；T24–T26 是后续扩展，不自动纳入本次目标。

## 主提示词

以下代码块内容可以直接复制。它是给未来开发执行者的指令，不是要求本次文档生成会话立即开始开发。

```text
请根据本机 Open WebUI 项目的 DD-1.0 设计开发文档，启动并持续执行一个开发 Goal，直到完成下文定义的 V1 技术交付与隔离验收。请执行开发、测试、修复和交付，不要仅返回建议、计划或骨架代码。

一、目标和工作目录

工作目录：项目根目录（即本文件所在仓库）。

最终交付：在现有项目内实现一个可运行、可验证、可恢复的智能学习系统 V1，形成：
选择学习者 → 上传试卷/作业或记录新学 → 自动分题与判错候选 → 可信批量确认 → 正式错题本 → 有证据的归因 → 针对性教学/数轴交互 → 独立变式测验 → 服务端判分 → 一次性复习调度 → 可追溯进度。

范围包括设计文档中的 V1 必需功能、一个正式接入的数轴模板、受控单 Agent 编排、必要管理/复核界面、薄原生 Tools 适配器、升级兼容和恢复能力。

默认不扩展到 T24–T26 的全部功能，不把更多视频/GIF、全学科自动判分、策略化自动入库等后续范围插入关键路径。缺少后续范围不影响本次 V1 技术目标；缺少核心上传、可信判分或正式入口不能降格称为 V1 已完成。

二、必须读取的依据

首先读取当前适用的 AGENTS.md（包括父目录及将编辑目录内的约定），然后按以下顺序读取：
1. docs/README.md
2. docs/DESIGN_DEVELOPMENT_SPEC.md
3. docs/IMPLEMENTATION_BACKLOG.md
4. docs/PAPER_HOMEWORK_IMPORT_DESIGN.md
5. docs/MULTIMODAL_AGENT_LEARNING_DESIGN.md
6. docs/UPGRADE_COMPATIBILITY_AND_RECOVERY.md
7. 按需要读取主规划、SECOND_REVIEW、脱敏运行快照和原型说明。

以 DD-1.0 总设计统一实现契约，按专题保留对应细则。遵循当前会话更高优先级指令和后续用户修正。发现冲突时记录明确决策并同步文档，不默默删减需求或降低权限、可信输入、判分、调度和恢复门槛。

2026-11-02 的版本、目录和功能是历史快照，不代表执行时事实。先核对已有代码和运行状态，再补充缺失部分；保留并复用已经完成且验证有效的实现，不重复重建。

三、Goal 的建立与持续执行

- 如果有 Goal 工具，先读取当前目标；仅在没有未完成目标时创建本任务。存在同一目标时继续，存在其他未完成目标时按工具契约处理，不能覆盖无关目标。
- 只有用户明确给出预算时才设置对应预算，不自行编造 token 预算、绕过预算或宣称无限运行。
- 每轮从真实任务状态选择下一项可执行工作，完成实现和必要验证后继续，不在每个阶段结束时询问“是否继续”。
- 不因一次回复、一个模块完成、一个测试通过或完成文档而标记整个 Goal 完成。
- 用户只问状态时简要回答并继续目标；用户明确暂停、取消或改变范围时遵循用户指令。
- 使用当前工具契约管理 complete/blocked/paused 等状态；不要擅自把困难、单次失败或缺少非关键输入当作暂停理由。真实阻塞要如实记录，不通过反复空转制造进展。
- 工具或平台不支持 Goal 时，执行可用的持续开发流程并持久化断点；明确平台限制，不虚构自动续跑能力。

四、自主推进与授权边界

本任务授权你在现有项目内读文件、编写和修改源码、测试、文档、迁移文件、扩展部署模板，创建隔离开发/测试目录和本项目独立测试服务，安装到项目隔离环境的必要依赖，并在测试数据库执行迁移和故障恢复。网络、进程和文件权限仍按当前环境实际许可执行。

对可逆的项目开发、只读检查、独立单元开发和测试直接推进，不重复申请权限。可以在本项目创建开发文档建议的子目录，这不等于另建独立项目。

现有正式 Open WebUI 的停机/升级、覆盖持久化配置、生产数据迁移/删除、密钥轮换、向外部发送真实学生资料、产生新增付费调用或正式站外通知，须有当前会话中适用的明确授权和范围。已经有授权时按范围执行，不重复问；没有授权时先完成代码、隔离验证和具体变更清单，再把该动作列为唯一必要确认，不让它阻塞无关开发。

可以使用明确配置且已授权的模型/OCR测试连接与预算执行受控实测。没有凭据、额度或外发授权时，先完成 provider 适配器与模拟测试，记录真实集成待验证；不读取 WebUI 密钥库来替代授权，不因“已有模型名称”推断调用可用。

默认单执行者工作。可批量执行互不依赖的搜索和测试；未经用户或适用指令明确要求，不自行启用子代理、付费服务集群或外部协作。

五、首轮行动与工程路径

首轮只做短且聚焦的核对：项目说明、适用指令、当前源码/依赖/测试、运行与存储的脱敏摘要、未提交改动、任务状态和关键文档。已有 Compose 和教材脚本可能含凭证，禁止直接整段打印。

随后立即推进第一个可验证实现。不要连续多轮只审查、重写规划或列 TODO。已有代码时先运行相关验证并补缺；仅有设计时先建立独立服务和最小测试，再按工作包逐步扩展。

执行顺序参考：
S0：T01–T05，基线、恢复/可信入口探针、样本与模型能力；
S1：T06–T08，数据库、身份、授权、挑战、幂等、附件与 worker；
S2：T09–T12，整卷上传、分题、判错、批量复核、错题本与来源；
S3：T13–T20，归因、变式、调度、正式测验、判分、Agent、数轴和 Tools；
S4：T21–T22，运行观测、故障/恢复/兼容和发布准备；
T23：准备真实试用材料和流程，在有真实参与和时长证据时才记录试用结论。

不要求机械等待全阶段完成才能开发无依赖模块。例如模型额度缺失时，可继续身份、上传存储、调度、数据库、UI、模拟 provider 和测试。将待验证依赖与开发完成状态分开，不伪造依赖通过。

使用 FastAPI 独立服务、独立 SQLite/附件和持久化 jobs/worker；具体 ORM、测试与前端依赖优先复用已有可维护选择，新增依赖说明理由并锁定版本。不无故加入 Redis、Celery、图数据库或多个工具接入路径。

六、不可违反的业务要求

1. 学习者与账号分离，身份来自可信服务端，所有查询、附件、复核和写入执行学习者授权。
2. 整卷照片/PDF是真正 V1 入口，不能用仅单题文字输入替代。保留原件、页序、区域、小问、跨页和学生/教师笔迹区别；失败页必须可见。
3. 自动保存错题候选，可信界面批量确认正式入库。正确、错误、部分错误、未作答、无法判定分开；红色批注或模型高置信度不是充分证据。
4. 未批改资料的答案映射、定义域、单位和可解性需要校验；不支持或冲突的内容复核。不能靠两次模型答案一致自证正确。
5. 原始学生输入不可被模型补写替换。最终确认和答案提交不是模型可自由调用的工具，必须经资源/版本/操作/身份绑定挑战和可信回调。
6. 幂等、revision、cycle预留、租约与原子状态转移有真实存储约束；同批重试和并发不会重复记错或晋阶。
7. 导入外部试卷只形成观察与来源，不直接推进、清零或补跑已有复习；新目标确认后才首次建卡。
8. interval-v1 使用相邻间隔 [1,2,4,7,15,30] 天；stage 0–5、维护门槛、辅助复测和时区沿用设计。用可控时钟验证日期链和边界。
9. 教学与独立测验隔离。提示/答案发放前记录辅助；观看、拖动、刚看动画后答对、模型转述均不算独立掌握。标准答案不泄露给测前客户端或模型工具输出。
10. Agent 只编排允许动作，受步骤、预算、超时限制；不能自行批准、改分、改权限或修改阶段。
11. 数学精确图形由程序计算，模型只选择审核模板和合法参数；素材可暂停、逐步、静态回退及减少动态效果。离线 HTML 原型不是正式测验实现。
12. 未完成任务、模型失败、取消、未知结果不能写成成功。历史修订保留版本，必要时按冻结规则补偿/重放。
13. 核心业务不依赖 open_webui 内部包，不直接写 webui.db，不挂载正式 WebUI数据目录；原生 Tools 保持薄适配，独立服务显式配置模型连接。

七、持久化进度和断点续跑

启动实际开发后维护这些本地文件（已有时复用并校验，不覆盖历史）：
- docs/goal/STATUS.md：目标、范围、阶段、当前任务、已完成证据、阻塞、下一动作；
- docs/goal/TASKS.json：T01–T26 的状态、子步骤、依赖、实现路径、证据路径、未满足验收；
- docs/goal/DECISIONS.md：G0决定、设计偏差及理由，不写密钥；
- docs/goal/BLOCKERS.md：真实外部缺项、影响范围、已尝试办法、可继续任务和最小待用户动作；
- docs/verification/：实际测试、兼容、质量、恢复和浏览器验收报告；
- docs/goal/HANDOFF.md：运行方式、修改摘要、剩余门槛、Goal是否可完成及依据。

任务状态使用 planned / in_progress / implemented / verified / blocked / deferred 等清晰语义；implemented 不等于 verified。任务中存在待验证子步骤时不能只改总状态为完成。T24–T26 默认 deferred，T23 的人工/观察步骤保持真实状态。

状态文件在重要实现/验收或阻塞变化后更新，不为每个小工具调用写大量流水账。下一轮从状态文件和实际仓库恢复，核对证据仍有效，继续最早可执行未完成项；不要重新开始全仓审计。

Git操作保留用户已有改动。先识别是否已有仓库；确需初始化时添加适当忽略规则，避免嵌套到不适合的仓库边界。不要 git add .、提交凭证/附件/数据库，未经授权不 push、不发布、不改全局Git身份。

八、测试与验收

把规格中 QA01–QA15 的 V1 项映射到可执行测试与真实验证；QA16/QA17 对应后续功能保持 deferred，不伪称通过。

必须验证：
- 数据库新建/迁移、两个学习者隔离、挑战重放/过期/换人/旧版本；
- 多图/PDF、逐页覆盖、小问/跨页、错误答案映射、五类判定和原图回查；
- 批量确认、相同幂等键异载荷、并发提交、真实再错与重复来源区别；
- worker租约、取消后迟到、模型/存储/数据库故障和可恢复操作；
- 正式测验无答案泄露、原答保真、提示暴露、pending判分、复核替题；
- 调度日期、时区、维护准入、导入/提前练习不晋阶、最终结果至多应用一次；
- Agent预算和权限、数轴数学正确性、手机布局、可访问的交互与静态回退；
- 实际Open WebUI兼容入口、隔离配置和备份恢复，不能只测 API 或离线原型。

能使用浏览器时执行上传→复核→入库→复习→反馈的真实UI链路，保存不含个人资料的截图/报告；无法用浏览器则标为待验证，不把接口测试替代UI验收。

模拟提供商用于确定性回归；真实提供商/原生交互必须另列真实验证证据。合成样本能证明程序行为，不能冒充学科人工标注、真实卷面准确率或真实学生学习效果。

开发/验收集按文档或母题拆分，报告样本量、失败页、弃判、精确率、召回率、耗时和费用；不预设未测得的准确率承诺。必要权限/并发/调度测试全部通过，不降低测试标准迁就当前实现。

测试应与实际风险匹配；一次通过后仅在有相关变更、失败或未解问题时重测扩大范围，不反复跑同一测试消耗预算。严禁删测试、跳过核心断言、硬编码示例答案或启用 mock 后宣称真实集成完成。

九、上线与升级准备

生成独立开发/测试与部署模板、示例配置、锁定依赖、OpenAPI、数据库迁移、启动/关闭/恢复说明及脱敏发布manifest。开发测试可以运行；正式变更必须符合第四节授权范围。

演练使用独立目录、数据库、端口、网络和凭据，在副本第一次启动前阻断正式API、正式存储、通知和未授权外部调用。不能以端口不同证明隔离，也不能让旧/新程序同时写同一迁移后的库。

原卷、裁剪、确认版本、题目、学习事件、配置与密钥属于一致性恢复集合；按升级专题验证。只换回镜像不等于恢复。不能在开放写入后覆盖旧快照并宣称无数据损失。

十、完成判定

仅在以下条件全部满足时，将本次“V1技术交付与隔离验收”Goal标为complete：
A. V1必需功能在源码、迁移、UI和适配器中实际实现，无用于冒充功能的空方法、固定示例或不可达流程。
B. 必需自动化测试、真实UI链路与必要真实提供商/原生接入验证通过；失败项已修复并复验，不能以mock替代。
C. 本地隔离环境能按文档从干净状态启动，完成完整闭环，并可恢复自己的数据和业务状态；涉及现有基线的恢复验证结果明确。
D. 核心权限、幂等、调度和答案隔离满足QA门槛；范围内没有未解决的阻断缺陷。
E. 任务/QA追踪、运行手册、质量/兼容/恢复证据和交接文件与实际代码一致。
F. 正式切换及T23真实试用的准备材料已可审阅，尚待的实际授权、人工验收和真实时间被准确列出；没有把“技术交付完成”写成“项目正式上线及真实学习效果已完成”。

若核心真实验证仍因缺凭据、模型/OCR、样题、浏览器或授权被阻断，继续其他可实施任务；穷尽独立工作后按Goal工具规则记录阻塞和精确缺项，不能自签完成。

不能用加快系统时钟、模型扮演学生或虚构7–14天日志完成T23。T23后续根据真实条件推进；T24–T26只有用户扩大范围时才启动。若用户明确要求把正式上线或T23纳入同一Goal，则扩大目标完成标准，未经真实验收不得complete。

十一、沟通与最终交付

开始时简要说明即将执行的实际工作，之后在重要结果、阶段完成或阻塞变化时给出简短中文进度。不要每完成一步就结束等待“继续”。

真的需要输入时只问影响当前工作的最小问题，说明哪个具体动作需要、依据是什么；同时继续独立工作，不反复询问已获授权事项。

最终交接包含：
1. 实现的V1能力和真实运行入口；
2. 代码、API、迁移、UI与部署配置的文件位置；
3. 实际运行过的测试/浏览器/模型/恢复验证及证据；
4. 尚待正式授权、人工审题或真实试用的明确事项；
5. 已知限制、后续范围和恢复方式；
6. Goal状态与完成/阻塞依据。

现在开始：读取文档与实际状态，建立或恢复目标和任务记录，完成第一个可运行且经过验证的开发增量，然后持续推进上述目标。
```
