# 模型、Agent、绘图与代码动效如何进入学习闭环

统一实现契约见 [设计开发总文档](DESIGN_DEVELOPMENT_SPEC.md)，开发顺序见 [任务与验收清单](IMPLEMENTATION_BACKLOG.md)。本专题保留教学与视觉设计细则。

日期：2026-11-02。基于主规划 R2 与升级兼容方案的增量设计。

U1 需求衔接：新增整份试卷/作业上传与错题收集，详见 `PAPER_HOMEWORK_IMPORT_DESIGN.md`。该入口优先于批量扩展视觉模板；本文离线原型不提供上传识别功能。

本轮交付：能力设计与一个离线数学交互原型；不调用在线模型/绘图接口，不部署新服务，不向现有学习数据写入成绩。这里的 Agent 指产品内受控的任务编排能力，不表示本轮启动了多个执行代理。

## 1. 让四种能力分别解决一个学习问题

| 能力 | 首要任务 | 合适的输出 | 不能直接作为依据的内容 |
| --- | --- | --- | --- |
| 多模态模型 | 理解题意与学生步骤，找到可能卡住的位置 | 待确认转写、诊断假设、分级解释、变式草稿 | 只看最终答案就断定错因；未经校验的题目与评分 |
| 学习 Agent | 按目标、证据和预算安排下一步，调用允许的工具 | 今日任务、追问、教学材料选择、练习/复测工作流 | 模型自行确认学生答案、修改成绩或直接推进阶段 |
| 绘图工具 | 建立生活情境、帮助辨认对象、组织文字关系 | 题目情境插画、诗文场景、经过审核的结构说明图 | 精确几何、坐标、数量和公式的自动正确性 |
| 代码可视化 | 让数量关系和操作过程可验证、可控制 | 数轴移动、等式变形、分组进位、交互实验、短动画 | 仅因画面播放或学生拖动过，就认定掌握 |

推荐主线：**先发现卡点 → 选择最小必要表达 → 学生预测/操作 → 学生解释 → 换题独立测试 → 更新复习计划。** 对简单问题只用一句话或一张图；过程确实需要演示时才增加动作。

## 2. 模型怎么帮助“学、练、错、析、测”

### 输入理解与诊断

- 图片题先识别原题、符号、图形标记和学生步骤；生成草稿让学生确认，不因模型能看图片就跳过转写复核。
- 整份试卷/作业先检查页序与质量，再分题并分别提取原题、学生笔迹、教师批改和参考答案；自动保存候选，可信界面批量确认正式错题。勾叉/扣分只是判定依据，模糊、冲突与缺步骤单列复核，不能用图像生成补造原题。
- 区分“答案错”“步骤有错”“题目条件缺失”和“无法判断”。例如 `-3 - (-5) = -8` 可以提示其可能混淆了减法与负数，但仍需追问其原本思路。
- 将诊断映射到稳定知识点与错因标签，用于检索审核过的教学模板；缺少适合模板时先文字解释或转人工复核。

### 因人调整解释方式

- 年级与当前课程决定用词、例子及符号复杂度。
- 相同知识点可准备具体物件、示意图、符号运算三种表达，学生能说清一种后逐步连接到另一种。
- 提示分级：先问下一步；再提醒相关规则；最后才演示完整过程。每次提示都记录辅助程度。
- 模型可以追问“你为什么向左走？”并比较步骤；不能只输出“你粗心了”。
- 上传错题进入教学前保留原卷定位与订正历史；Agent 按已核验的题意和错因选择演示。未确认的 OCR 字符不能直接成为精确动画参数，导入正确/错误也不直接推进复习阶段。

### 生成练习与复习材料

- 变式基于已审核母题、约束和目标难度生成，沿用 R2 的校验/判分门槛。
- 生成“错法与正法对照”“一句话规则”“待填空步骤卡”“预测下一步”等复习材料。
- 制作教学动画时可以显示解释；独立测验使用新的题目和干净的交互，避免复播原答案后马上计为独立掌握。

## 3. Agent 的角色：编排工具与学习步骤

建议首期使用一个编排器配合多个明确动作；以下是逻辑职责，不要求分别部署成六个自主 Agent，也不要求每次都调用六轮模型。

| 逻辑职责 | 输入 | 决策/动作 | 结束条件 |
| --- | --- | --- | --- |
| 任务规划 | 到期卡、时间预算、学习者授权 | 选择当日目标与任务顺序 | 生成有限任务清单 |
| 教学对话 | 可信作答、知识点、已有提示 | 追问、讲解、选择表示方式 | 学生能解释，或需要换一种表示 |
| 视觉编排 | 学习目标、错因、课程约束 | 选模板、生成场景参数与分镜 | 可校验的 `visual_spec` |
| 题目生成 | 审核母题、目标卡、变式条件 | 生成候选并调用校验器 | 合格题或明确失败 |
| 评测编排 | 冻结题目、真实 UI 输入 | 请求判分/复核，提供反馈 | 最终可信结果或待复核 |
| 进度回顾 | 有效学习事件、提示记录 | 概括薄弱点与下一轮安排 | 可追溯总结 |

受控执行循环：`读取状态 → 提议下一动作 → 校验权限/预算/前置条件 → 执行允许工具 → 保存事件 → 继续或结束`。

- 核心状态保存在学习库，不把长聊天历史或模型记忆当作唯一状态。
- 允许动作使用枚举和明确参数；身份授权、草稿确认、最终成绩、调度转移仍由 R2 的服务与可信 UI 完成。
- 限制每轮工具次数、重复生成次数、总费用和时间；无新证据时停止循环并说明原因。
- 事实/数学校验优先程序与审核材料；一个模型换个“审核者”身份自检不能当作独立正确性证明。
- 错误处理必须有退路：生成失败可使用已审核题库；动画失败回退静态步骤；素材缺失可文字说明。不能编造生成成功或晋阶结果。
- 学生需要结束时保留进度，下一次从真实任务状态恢复；提醒与站外通知仍遵循原规划的授权与渠道要求。

## 4. 绘图能力的用法

本机已经有“学科思维导图与教学插画绘制”工具。可以先复用其情境插画能力，并延续升级方案中对内部模块依赖的回归要求。本轮仅只读核实工具存在，没有发起图片生成。

### 推荐使用

- **题目情境**：把“书架上有两类书”“购买不同价格的文具”等情境画清楚，关键数值与数量标签由代码叠加。
- **语文阅读**：画人物、地点和事件场景，辅助复述；图像标明“根据文本绘制的情境示意”，文本是判断依据。
- **英语表达**：同一人物在不同时间/地点的场景，用于造句和比较表达；文字答案按阶段隐藏。
- **知识组织**：模型输出结构化知识点关系，再由图形组件布局；关系正确性先审核，不能让画图模型自由添节点和关系。
- **错因卡片**：学生错法与正确规则并排，关键差别只标一处；先让学生发现差异，再给解释。

### 精确内容交给结构化绘制

数学刻度、几何长度、坐标轴、角标、公式和汉字标签由 SVG/HTML/公式组件根据已验证数据生成。生成式图片可提供角色和环境；与解题有关的量和关系必须来自结构化数据。图像美观不等于内容正确。

复杂地图、地理过程和生物结构在扩科时使用经核对的材料与标注，不因图像逼真就视为事实。

## 5. 代码动效、交互和动图如何分工

| 形式 | 适用场景 | 学习者如何参与 | 发布要求 |
| --- | --- | --- | --- |
| SVG 静态图/分步图 | 精确关系、错法对照、总结 | 标注、补空、解释一步 | 数学量一致，有文字替代 |
| HTML/SVG/Canvas 交互 | 数轴、等式、分组、参数变化 | 预测、逐步操作、改变参数 | 可暂停/重置/键盘操作；状态可复现 |
| 短循环动图 | 一个操作的快速回忆线索 | 先回忆，再按需查看 | 同时提供静态版；看过即作为辅助暴露记录 |
| 可控短视频 | 多步过程、较完整讲解 | 暂停预测、回看某一步 | 支持播放控制、字幕与静态分镜 |
| 代码生成知识短片 | 多个相连概念的专题复习 | 看后解释、做新题 | 先事实表与分镜，再渲染；专门审查 |

首期建议优先交互式小实验和静态步骤卡。短片可从一个约 20~60 秒的过程试起；这是内容设计建议，不是已证实的最佳学习时长。GIF 更适合作为短提示素材，不能替代需要暂停、预测和输入的交互。

技术实现选择：精确二维图优先 SVG；动态场景可用 Canvas；数学视频可评估 Manim；经审查的帧序列可通过 FFmpeg 编码。工具版本按升级方案固定，先验证原型再决定依赖，不能同时安装一整套未用到的动画框架。

### 展示时遵循的规则

- 一个动画解决一个明确误解；同一时刻突出一个关键变化。
- 先例子后规则：先看到移动/分组/两边同操作，再总结符号法则。
- 关键一步先停住，要求学生预测；揭示后让其解释为什么。
- 支持暂停、逐步、重播、文字说明和减少动态效果；颜色之外还用箭头、标签和方向文字表达差异。
- 内容不是越动越好。把装饰动作和教学动作区分；只有能说明数量或因果变化的动作进入主画面。
- 看完、点击过、拖动过只算参与记录；掌握证据来自之后的真实、无提示变式作答。

## 6. 三个可直接进入原型的例子

### A. 七年级数学：减去负数

错误例：`-3 - (-5) = -8`。该例是演示素材，不是从真实学生记录提取。

1. 模型询问学生为什么向左走，确认是否混淆了两种符号。
2. 代码画出带刻度数轴，把起点放在 -3。
3. 显示 `-3 - (-5)`，先让学生预测最终位置。
4. 展开为 `-3 + 5`，箭头向右移动 5 格，停在 2。
5. 并排保留错误的“向左 5 格”轨迹（-8），强调两条路径用了不同操作，不用含糊的“两个负号总变正”。
6. 学生用一句话解释“减去一个数等于加上它的相反数”。
7. 关闭解释后换 `-4 - (-7)` 等变式，记为当堂巩固练习；不能因刚学完就答对而直接当成长间隔掌握证据。后续到期、无提示的真实测验才按 R2 规则参与调度。

本轮离线原型：`prototypes/signed_numbers.html`。仅使用本地页面计算和演示，没有认证、在线模型和业务 API；答案存在页面逻辑中，因此不是可部署的正式测验工具。

已完成原型检查：210 组计算参数、5 组非法输入、六道预设示例、预测/提示/逐格/播放暂停/换题行为，以及桌面和 390px 手机布局。修正了初版手机图形裁切；检查结果仅说明此离线示例的计算与交互，不代表正式服务或教学效果已通过验收。使用与验证边界见 `prototypes/README.md`。

### B. 七年级数学：等式两边做同样的操作

以 `2x + 3 = 11` 为例：先问两边应怎样变化；演示同时减 3，得到 `2x = 8`；再同时除以 2，得到 `x = 4`。另外展示“只从左边减 3”的不等价结果，由学生指出哪里破坏了等式。

图形中的数量和公式同步计算。若采用天平比喻，必须清楚说明它用于解释等量关系；涉及负数时另换适当表示，避免把负重量等比喻当成真实物理模型。

### C. 二年级数学：进位是重新分组

以 `23 + 19 = 42` 为例：把 23 和 19 分解为十位组与个位；个位 `3 + 9 = 12`，从 12 个单位中取出 10 个组成新的“一十”，剩余 2 个单位；与原来 3 个十合并得到 4 个十和 2 个一。

学生先预测“为什么要向十位加 1”，再拖动或逐步合成一组十，最后用不同数字独立计算。动效中的单位总数始终是 42，不能为了视觉效果增减物件。

## 7. 每日复习中的媒体选择

| 学习状态 | 推荐材料 | 怎样计入记录 |
| --- | --- | --- |
| 初学或首次明显误解 | 具体图示＋可控完整过程 | 教学/暴露事件，不算独立测验 |
| 短间隔巩固 | 停在中间步骤，要求预测下一步 | 有提示的练习，单独标记 |
| 到期独立复测 | 新变式，隐藏提示、解析和动画结论 | 符合 R2 条件时才参与调度 |
| 独立复测失败 | 显示对应的一小段纠错演示 | 先保存有效作答结果，再记辅助教学事件 |
| 维护复查 | 新情境、少提示、要求解释关键理由 | 按规则判分；动画可按需学习但不能当作无提示成功 |

不同天数只是调度规则，不能机械规定“第 7 天必须看动画”。由最近真实错误和目标知识点决定是否使用媒体；同一目标的动画与练习共享复习卡，不为每个素材新增一张重复卡。

## 8. 接入现有架构并保持可升级

```text
Open WebUI 学习教练
       │ 薄原生 Tools / 经验证的展示交互
       ▼
Learning Service
       ├─ 受控任务编排 + 学习/测验状态
       ├─ 教材与审核母题
       ├─ 模型解释 / visual_spec 候选
       └─ 已审核视觉模板与素材注册表
                       │
                       ▼
              隔离的媒体渲染 worker
              参数化场景 → 检查 → 静态图/交互/视频
```

- 首期模型生成结构化场景参数，不自由生成任意可执行代码。模板由开发者编写、审核和测试，模型只选择模板及允许的参数。
- `visual_spec` 最小字段：知识点/训练目标、教学目的、模板版本、合法参数、步骤顺序、提示等级、文字替代、出处引用、可见范围；不接受任意脚本、远程资源地址或 shell 命令。
- 核心渲染逻辑和依赖独立于 WebUI。Open WebUI 官方文档提供 Artifacts 与 Rich UI 展示能力，但需在本机 0.12.5 验证 iframe、脚本、资源、移动端和刷新行为，不能因文档支持就标记已集成。
- Rich UI 可以作为教学材料入口；HTML 显示成功不等于可信身份或成绩提交链路已通过。正式答题仍遵循 R2 的挑战、原始输入、后端判分和权限约束。
- 未来如引入模型生成代码，先进入隔离构建/渲染作业并审查，限制网络、CPU、内存、文件与运行时间；不能给其宿主机终端、Docker socket、正式数据库或提供商密钥。
- 生成 HTML/脚本不能在主应用同源环境无限制执行；评估独立来源、受限 iframe、内容安全策略和消息来源/结构校验。客户端消息不直接修改成绩。
- 未验证的素材为草稿；数值/公式/步骤通过检查、内容审核后才进入共享素材库。个人题图和定制诊断按学习者权限隔离，不放入跨用户公共缓存。
- 素材缓存键包含模板、参数、课程和内容版本；可共享的是无个人信息的审核模板。教学资产记录生成版本与用途，升级时可回退到前一版素材。

## 9. 记录什么，怎样判断是否有帮助

增加媒体相关的辅助事件：素材请求/发放、可观测展示、暂停/重播、预测提交、提示使用、模板版本、所属知识点。客户端“已看完”仅作为交互指标，不作为可信学习成绩。

素材包含答案/提示时，在服务发放前记录该次辅助暴露；不能只等浏览器自报“看过”才取消独立评分资格。发放不等于确实观看，因此报表分别显示已发放、可观测观看与后续作答。

优先观察：

- 看过纠错演示后，是否能用自己的话解释关键一步。
- 换数字/换情境后，独立正确率和同类错误复发是否变化。
- 相同任务预算下，完成时间和提示依赖是否改善。
- 是否因动画分心、反复播放而挤占独立练习。

报告带样本数和条件。小范围前后比较只能提供线索，不把新鲜感、观看量或单次答对当作因果证明。现有研究也发现过装饰性动画增加负担、降低表现的情况；本项目优先验证与任务直接相关的演示，不能宣称“有动画一定学得更好”。

## 10. 落地顺序与范围

| 增量阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| M0 教学设计与原型 | 一个目标、正确过程、错误对照、预测点、离线交互 | 数值和讲解一致，能逐步操作，明确原型边界 |
| M1 单模板接入 | 数轴模板、素材注册、提示暴露记录、原生展示探针 | 原型通过后再接业务身份；展示失败可回退静态内容 |
| M2 三模板教学库 | 数轴、等式、十进制分组，配变式与内容审核 | 边界参数正确，覆盖对应错因，支持移动端与减少动态效果 |
| M3 复习与Agent编排 | 根据实际任务选择媒体，教学/测验隔离，进度指标 | 无绕过确认/判分，无重复晋阶，教学素材不泄露测前答案 |
| M4 导出与扩科 | 审核分镜导出视频/动图，逐步扩展学科 | 渲染隔离、版本固定、来源可查、各学科重新验收 |

这些是 R2 的增量，不默认为已经包含在 11~17 人日基础闭环开发估算内。原型不等于 M1 接入完成；先验证单模板与本机展示能力，再估算正式增量工期。当前不扩张到多个自治 Agent 集群或自动生成全学科动画平台。

U1 更新后的优先级：先保证上传/分题、可信批量入库和复习来源链路通过 U0–U3，再批量扩展 M2/M4；已完成的 M0 原型及 M1 单模板展示验证可继续复用，不把整卷导入隐藏在“未来 OCR 增强”中。两类增量与基础闭环应合并排期，共用身份、作业和复核机制只估算一次。

## 11. 离线原型分镜与依据

数轴原型采用实际数学对象作为主体，借鉴 `vibe-knowledge-film` 的“先例子、后规则；动作真的发生；数字由程序计算；允许停下来解释”的设计方法。本轮没有制作该技能定义的完整知识短片。

| 步骤 | 屏幕内容 | 学生动作 | 核心理解 |
| --- | --- | --- | --- |
| 预测 | `-3 - (-5)`，结果隐藏 | 输入最终位置 | 暴露当前判断，不先给答案 |
| 展开 | 起点 -3，减数 -5 的相反数为 +5 | 请求提示或下一步 | 操作转换的依据 |
| 演示 | 数轴上向右移动 5 格 | 播放/暂停/逐步 | 方向与长度对应运算 |
| 对照 | 正确终点 2，错误路径终点 -8 | 解释两条路径差别 | 不能把“减去负数”当成“加上负数” |
| 变式 | 新题 `-4 - (-7)` 等，图解重新隐藏 | 提交预测，再选择图解 | 提供后续独立测验设计的示意 |
