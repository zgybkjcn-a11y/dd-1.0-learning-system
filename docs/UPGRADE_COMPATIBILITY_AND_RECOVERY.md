## 1. 核心决策

1. 官方 Open WebUI 镜像保持原样，学习业务以独立容器、独立数据库、独立附件存储运行。
2. **v1 唯一入口为薄原生 Python Tools 适配器**，通过内部版本化 HTTP/OpenAPI 契约访问学习服务。外部 OpenAPI 工具连接后置，敏感服务命令不直接注册为模型工具；不同时维护两条交互路径。
3. 学习系统核心逻辑不导入 `open_webui.*`，不查询或修改 `webui.db`，不挂载 Open WebUI 数据目录。
4. Open WebUI、适配器、学习服务、学习库 schema、调度规则、提示词/课程配置分别版本管理；每次发布记录一个经过验证的组合。
5. 升级前用独立数据副本演练，正式切换设维护窗口。旧程序回退必须考虑数据库已经迁移，不能只改镜像版本。
6. 日常升级保持应用密钥和数据挂载一致；密钥轮换单独作为受控变更处理。

## 2. 哪些内容由谁持有

| 内容 | 权威存储/管理位置 | 升级保护措施 |
| --- | --- | --- |
| Open WebUI 账号、聊天、原生模型配置、工具定义、权限、知识库关联 | Open WebUI 原生存储 | 完整一致性备份；原生迁移；升级前后逻辑对账 |
| 错题、学生原作答、诊断、复习状态、判分记录、学习者授权 | 独立 Learning Service 数据库 | 自己管理迁移和备份；Open WebUI 升级不同时迁移学习库 |
| 试卷/作业原件、页图/分题区域、学生作答/教师批改、答案映射、确认版本、审核母题与课程目录 | 学习服务自己的存储 | 保存原始文件、处理和确认版本；不把 WebUI 文件 ID 当唯一副本；备份恢复核对错题到原卷的关联 |
| 教材原始 PDF、目录、版次、页码映射 | 本地原始教材与课程清单 | 版本/哈希清单；可重建索引；原始资料不得仅存向量库 |
| 当前 Open WebUI 知识库及向量索引 | WebUI data 及实际配置的外部存储 | 与数据库/原始文件同步备份；重建索引单独测试 |
| 适配器、工具源码、学习教练 system prompt、部署模板 | 项目代码仓库 | 版本、差异审核、发布清单；不提交密钥和学生数据 |
| WebUI 密钥、业务服务凭据、模型提供商密钥 | 受限 secrets/.env 或秘密管理系统 | 加密备份、权限控制；与发布清单记录关联但不明文入 Git |

**两类来源不要混淆**：数据库备份保存“当时实际生效状态”；代码仓库保存“希望发布的受管配置”。不能每次启动无条件覆盖数据库，把用户在界面里改过的设置抹掉。

## 3. 尽量缩小与上游的耦合

```text
官方 Open WebUI（可独立升级）
       │
       └─ 极薄 Python Tools 适配器（v1唯一入口）
                                         │ 内部HTTP契约
                                         ▼
                              Learning API /api/v1
                                         │
                         业务逻辑、调度、学习库和附件
                         独立镜像 / 独立版本 / 独立备份
```

### 3.1 接口与扩展约束

- `operationId`、字段含义、错误结构和身份约定稳定；新增字段尽量保持向后兼容；不兼容变更发布 `/api/v2` 并保留过渡期。
- API 使用 `request_id`、幂等键、状态版本，防止上游升级后出现重试策略变化而重复入库、重复晋阶。
- 程序状态由学习服务决定。模型和插件只提交原始输入，不能传入任意“判对/晋阶”结果。
- 服务需要认证并校验账号到学习者的授权；用户 ID 必须来自可信服务端上下文。可伪造的身份头不能独立构成认证。
- 不依赖上游前端 DOM、私有组件路径或直接修改 Svelte 页面。结构化答题若超出原生事件能力，可采用学习服务自己的小型页面，UI API 同样保持独立。
- OpenAPI 不能完全替代原生工具的输入/确认交互；保留这一小块适配，并对文档化上下文和事件做兼容测试。
- `__event_call__` 的成功/取消/超时/断线结果按候选版本实际结构校验；非空错误对象不能当作用户同意。确认与答案提交仅由可信回调调用，不注册为模型可自由填参的工具。
- v1 原生交互在 P0 必须验证；若失败，先设计后备页面的会话认证与挑战兑换、调整工期，再推进交互依赖工作。没有可验证输入链路时，正式测验保持关闭。
- 不把额外依赖安装进官方运行容器；学习服务自己锁定依赖。原生适配器尽量只用标准库与已验证的宿主能力，避免依赖包版本相互影响。
- 若必须使用内部接口，集中在一个适配文件，记录内部依赖与支持版本；升级只调整该适配层，不能散落到调度或数据层。

### 3.2 本机已有的具体兼容风险

现有“学科思维导图与教学插画绘制”工具直接引用：

```python
from open_webui.routers.images import CreateImageForm, image_generations
from open_webui.models.users import UserModel
```

它在上游变更函数签名、请求对象或用户模型时可能受影响。建议第一阶段先导出源码、记录依赖、建立绘图回归用例；再评估封装为单独兼容适配器，或改用明确的外部绘图服务契约。不要在尚未验证功能等价时直接替换。

新建学习工具不得照搬这些内部导入。部署前列出所有 `open_webui.*` 依赖，做到来源明确、测试覆盖。

### 3.3 教材和 RAG 也需要隔离

- 原有知识库继续作为教学资源使用，但学习服务必须保留审核过的教材片段/课程目录与出处，不能直接耦合 WebUI 的向量库物理结构。
- RAG 访问集中到单一检索适配器；若上游检索接口调整，只修改该适配器。找不到资料时提示不可用，不能编造依据。
- 上游附件读入学习服务时先校验访问权限，再保存受管副本或稳定的自有对象引用、来源 ID 与哈希；不能让原聊天被删除后错题原图随之失去唯一副本。
- U1 上传与附件取回仅在适配层处理；OCR/PDF/分题依赖安装到独立 worker。重跑识别产生新版本，不能随 WebUI 升级静默覆盖已确认转写、原作答或判定。多页任务进度、幂等批量确认和取消后迟到结果也须回归；导入外部成绩不能冒充独立复测。
- 向量索引可重建，但原始文件、版次、权限和知识库关联不可因此省略备份。embedding、切块或 OCR 升级与 WebUI 升级分开评估。
- 多模态增量的视觉模板、场景参数、审核记录和学生私有素材也由学习服务独立持有；渲染依赖/素材版本单独固定，不安装到官方 WebUI 容器中。Artifacts/Rich UI 展示与可信成绩提交分别验收，参见 `MULTIMODAL_AGENT_LEARNING_DESIGN.md`。

## 4. 镜像、配置与发布版本

### 4.1 固定版本，不自动追随 :main

当前核验基线：

```text
Open WebUI: 0.12.5
Image digest: omitted from the public document; pin and verify a digest before deployment.
Database migration revision: 0bd252b206fb
Learning Service / Adapter: 本地 DD-1.0 schema revision 6；独立 Compose/迁移/恢复和薄适配器有确定性证据；隔离 Open WebUI 0.12.5 已注册并通过原生 loader/合成回调探针，真实浏览器组合与最终可信 UI 回调尚未验证
```

实施时把镜像引用配置化，使用经过验证的发布版本和 digest；digest 是实际拉取内容的锁定依据。保留当前可回退镜像，不在观察期清理旧镜像。

采用“收到更新通知 → 审阅发行说明 → 演练 → 人工发布”的策略。常规更新安排固定窗口，安全修复按影响优先处理；不使用无人看护的自动升级。此方案不阻止更新，而是给更新建立证据和回退路径。

### 4.2 环境变量与界面配置的责任边界

当前 0.12.5 源码显示：持久化配置开启时，已存入配置表的键由数据库提供值，没有该行才回退到默认值；禁用持久化则使用默认/环境配置路径。环境变量不是所有设置的最终权威。

- Compose/.env 管部署级设置：镜像、端口、数据路径、网络、密钥引用。
- 管理员界面/API 管已经持久化的模型连接、工具绑定、RAG 和用户权限等设置；实际支持的导入导出范围按候选版本验证。
- 在发布清单中标记每个受管项的来源，升级前导出/保存实际配置摘要，升级后逐项核对。
- 不把 `RESET_CONFIG_ON_START` 或禁用持久化当作常规升级办法；它们会改变配置加载行为。
- 同一个受管配置既允许 UI 编辑又有文件版本时，导入脚本做三方比较：上次发布值、当前实际值、本次目标值。遇到人工修改先报告差异，不静默覆盖。
- 导入工具/模型采用稳定 ID 的幂等更新；核对模型、工具、知识库之间的绑定，不能重复创建同名对象代替更新。
- 保持已有 `WEBUI_SECRET_KEY`。迁移到受限配置时保留相同值；轮换已暴露密钥要单独验证会话及加密数据影响，不能与软件升级顺便执行。
- 0.12.5 中部分 OAuth 加密密钥默认关联 `WEBUI_SECRET_KEY`。密钥丢失不能靠数据库文件自动补回；相关密钥也必须受保护地备份。

### 4.3 发布清单与兼容矩阵

每次发布至少记录以下内容，敏感值只保存引用或安全指纹：

| 记录 | 用途 |
| --- | --- |
| WebUI 版本、镜像 digest、升级前后 DB revision | 明确实际运行内容和迁移路径 |
| Adapter 版本与依赖清单 | 缩小上游兼容修复范围 |
| Learning API/镜像/schema 版本 | 防止误把不同业务版本混用 |
| Prompt、调度规则、课程目录版本 | 区分软件回归与教学策略变化 |
| 模型配置 ID、工具绑定、知识库引用、检索配置摘要 | 升级前后功能对账 |
| 备份 ID、校验和、恢复演练记录 | 证明备份能够恢复，不只是文件存在 |
| 测试结果、已知限制、批准发布的时间 | 决定是否进入真实使用 |

兼容矩阵只写“已经实际测试”的组合，不凭主次版本号推断兼容，也不把 0.12.5 正在运行等同于尚未开发的学习服务已获认证。

## 5. 备份与数据恢复设计

### 5.1 必须保存的集合

对于当前本机小规模部署，优先选择短维护窗口的一致性备份：

1. 冻结新写入，排空进行中的请求，暂停调度器与后台 worker，然后停止相关写进程。
2. 备份完整 `data/` 及学习服务数据/附件目录、**原始教材文件及其哈希清单**、部署配置和受保护密钥；本机原始教材还位于相邻 `textbooks/`，不能只备份 Open WebUI 项目目录。若原件在已有独立受保护备份中，记录不可变快照定位并验证可恢复，清单本身不能代替文件。保留文件属主及权限。
3. 记录镜像、数据库 revision、备份时间、文件校验和与配置摘要，备份集标记为不可修改。
4. 将备份复制/解包到新位置，执行数据库完整性检查，并启动匹配旧镜像验证登录、教材与学习数据。
5. 备份本身含隐私和凭证，实施加密、受限访问和异地/离机副本；备份位置与保留周期按容量确认。本轮没有复制到外部存储。

热备时 SQLite 使用 backup API，不只复制正在写入的单个 `.db`；即使数据库热备一致，附件与索引仍需一致性方案。单机首次实现先采用冷备，避免过早增加复杂度。

配置导出不能替代数据库/文件备份；仅备份 `webui.db` 也不能保证附件、索引与密钥齐全。未来如改用外部数据库或对象存储，应将这些外部资源纳入同一发布恢复方案。

### 5.2 可接受的恢复目标

- **开放真实用户前的失败**：保持写入冻结，恢复正式升级前快照，可以做到相对该快照无真实用户新增写入损失。
- **开放真实用户后的失败**：先冻结并保存故障现场；恢复旧快照会丢失快照后的 WebUI 新记录。必须评估增量导出/重放或向前修复，不能承诺无损直接回退。
- 学习服务如本次未改变且仍兼容，优先保留其新学习事件，仅修复/回退受影响的 WebUI；同时核对账号映射、新建用户、源附件和会话引用，避免悬空关联。
- 如果必须协调恢复多个存储，按同一一致性时点恢复并明确损失范围；不能无条件把全部学习数据一起覆盖成旧版本。
- 恢复耗时与最大可容忍停机时间需要实测后再承诺；目前没有完成演练，不能保证几分钟恢复。
- B1 的数据校验之外还需保留账号身份 issuer/subject 映射、受控配置和删除记录。恢复后无法关联的账号默认无学习记录访问权，不能按同名/同邮箱自动认领。
- 开放写入后的增量保护是**恢复决策流程，不是已实现的跨版本自动重放工具**。未有经过验证的导出/迁移路径时，优先在冻结写入状态下向前修复；若只能恢复旧快照，必须明确新增数据损失范围并取得实际数据负责人的决定，不能声称无损。

## 6. 一次升级的标准流程

### A. 候选版演练

1. 阅读从当前版到目标版的发行说明，列出数据库、认证、工具、上传与 RAG 变更；不假设跳版本或只升补丁号就天然安全。
2. 在一致性备份上创建独立演练数据副本。使用不同 Compose project、容器名、端口、网络和数据目录，确认最终解析出的挂载路径。
3. 演练 WebUI 只能连接演练学习服务、演练数据库、复制/测试用附件。**不能只克隆 WebUI，再连接正式学习服务。**
4. **在克隆容器第一次启动前**完成网络出口默认拒绝和正式目标访问阻断；使用独立内部网络且不加入正式服务网络，不挂载宿主机 Docker socket 或非必要目录。之后在隔离状态下禁用/替换克隆数据库中的自动任务、回调、工具连接和正式凭据，经验证再逐个开放测试目标。只改 `.env` 不足以覆盖已经持久化的设置。
5. 原密钥如为解密所需只在受控副本使用；演练实例限制访问并使用独立浏览器环境，不能公开暴露携带生产凭证的克隆。
6. 启动候选镜像，让其迁移副本数据库；执行下述兼容回归，记录耗时、schema 和功能变化。
7. 演练失败则修复适配层或暂缓该版本，正式实例继续使用原版。

演练启动检查必须形成可核验结果：最终解析挂载路径不含正式数据目录；演练服务访问正式学习 API/通知接收端被网络或凭据拒绝；默认不允许真实模型/OCR请求；待克隆配置完成清理才用测试凭据放行受控调用。环境名或单独端口本身不是隔离证据。

### B. 正式切换

1. 演练通过后安排维护窗口：关闭正式用户入口并停止旧版 WebUI；学习服务进入拒绝新写入的维护状态，暂停领取新作业并排空在途调用。冻结超时或仍有未知写入者时中止升级，不带着未完成任务直接拍快照。
2. 创建**新的正式升级前备份 B1**。演练所用的旧备份 B0 不能直接拿来覆盖正式数据，否则会丢失演练期间的新记录。
3. 只升级 WebUI 与必要适配层；学习服务、业务 schema、模型提供商、embedding 和提示词策略保持已验收组合。
4. 如果目标版本包含数据库迁移，停止所有访问该数据库的旧版 WebUI 副本/worker，仅让一个候选实例执行迁移，再启动同版本实例。
5. 新版先仅通过受限验收入口访问，不能仍将所有网卡的宿主机端口对真实用户开放。维护状态下完成数据对账、登录、工具调用、教材检索和闭环冒烟测试；验收写操作限独立测试学习者并留痕，通过后才恢复后台任务和正式入口。若尚未建立可验证的入口隔离，则不执行正式迁移。
6. 记录正式发布 manifest，观察错误率、任务积压、重复提交和检索变化，保留旧镜像与 B1。

旧新版 WebUI **不能同时读写同一个已经迁移的数据目录**。对于当前部署，短维护窗口通常比数据库迁移期间强行零停机更容易验证和恢复。

### C. 失败处理

- 只坏一个可选扩展：禁用该扩展或切回已验证适配器，优先保留聊天与核心学习数据服务。
- 确认/身份传递失效：学习写入入口关闭或降为只读，提示维护；不得推测用户身份或把未经确认的结果当成绩。
- 数据库迁移失败且尚未开放写入：停止候选实例，保存失败现场，恢复 B1 的匹配数据和配置，使用原 digest 启动并验证。
- 数据库已迁移：**只换回旧镜像不是完整回退**；不直接让旧程序读取新 schema，也不自行执行未经验证的 downgrade/stamp 操作。
- 已开放写入：进入上节的增量保护与人工决策流程，先保护新增数据，再选择修复或恢复。

### D. 业务数据库自己的发布约束

- WebUI 升级和学习 schema 升级分开发布。学习服务新增字段优先用向后兼容迁移，验证旧版服务能否读取；不把有损删列/改语义与普通发布混在一起。
- 学习服务自己的迁移同样先备份、暂停写入与 worker、由单一迁移进程执行，再升级所有写入进程。不能因为独立于 WebUI 就省略其回退设计。
- 事件重算使用记录在事件上的规则/判分版本；需要旧版本解释器时必须保留，不能在回退时用新规则重放旧成绩。
- 已删除资料恢复时应重新应用有效删除记录；备份保留与销毁纳入数据生命周期，而不是只保留越来越多不可清理的副本。

## 7. 升级回归检查

| 层次 | 必测内容 | 通过标准 |
| --- | --- | --- |
| 配置与原生数据 | 账号/角色、模型参数、系统提示词、工具绑定、权限、聊天、知识库文件关联 | 关键记录与基线语义一致；允许官方迁移新增结构，但不能丢原内容 |
| 接入契约 | 工具发现、参数类型、可信身份、附件权限、错误返回、上下文与交互事件 | 旧 API 契约仍可用，越权拒绝，模型不控制用户身份 |
| 学习闭环 | 新学/错题录入→确认→归因→今日任务→测验→判分→调度 | 结果可复现，重复提交不重复记分，测前不泄露答案 |
| 试卷/作业导入（U1） | 多图/PDF附件授权、原件取回、页码/区域定位、批量确认、失败恢复、重复导入、参考答案门禁 | 每项来源完整，无越权/漏页静默成功/重复错题；旧确认不能提交新版本；导入不直接改变已有阶段 |
| 资源与RAG | 代表性教材题、中文/数学符号、引用页码、图片加载 | 与人工参考相符；索引存在不等于检索有效 |
| 既有绘图工具 | 工具加载、请求/用户模型、绘图结果返回 | 已有功能仍可用；外部生成调用安排受控样例和费用预算 |
| 任务与故障 | 自动任务暂停/恢复、超时、重试、服务重启、写入中断 | 无重复通知、无重复任务、无半完成有效成绩 |
| 交互异常 | 取消、非空错误对象、过期/重放回调、账号切换、模型伪造确认 | 拒绝未验证确认；原始答案不被模型转述替换 |
| 演练隔离 | 初次启动、持久化外部连接、正式目录/网络、通知与模型请求 | 在清理配置前已经阻断正式副作用，并有可重复检查证据 |
| 恢复 | 完整性检查、旧镜像恢复、登录与附件/学习记录复验 | 实际恢复成功并记录耗时 |

测试分两层：先用模拟模型响应/固定样题验证确定性逻辑，再用少量真实模型调用验证工具集成。真实调用的非确定性不能作为忽略数据一致性失败的理由。

## 8. 对实施计划的补充

升级兼容工作前置到原 P0/P1，而不是等到第一次升级出故障再补。

| 时点 | 增补工作 | 工作量估算 |
| --- | --- | --- |
| P0 | 固定 digest、配置来源、已有工具归档、旧版恢复、可信交互探针 | 纳入主规划 R2 的 P0（2~3 人日），其结果决定后续接入可行性 |
| P1 | API 契约、幂等、独立存储、身份映射、业务迁移策略 | 纳入业务服务的基础设计 |
| P3 | 演练 Compose、配置差异报告、兼容矩阵、工具/绘图/检索回归 | 已纳入主规划 R2 的 P3（3~4 人日），不再额外叠加 |
| 每次升级 | 候选演练→正式新备份→维护切换→观察→归档 | 根据发行说明和首次演练耗时估算，不固定承诺 |

本轮建议的下一项实施工作是 P0：先锁定现有版本和数据保护基线，再开始业务开发；这不等于现在就升级 Open WebUI。

统一工期以主规划 R2 为准：P0~P3 共 11~17 人日，含 P4 修订共 12~19 人日，另需 7~14 天观察。后备独立页面、复杂手写/几何识别及新模型训练不在该估算内。
