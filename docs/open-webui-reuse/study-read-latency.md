# 伴学只读连接与尾延迟

B10 续批的机制说明。独立结果见[尾延迟验证](../verification/B10-tail-latency-2026-11-08.md)；首批缓存、12 秒总截止、取消传播和未达性能记录见[原约定](study-performance.md)。

只在三个同步读取边界内复用 SQLite 连接：伴学路由的身份/档案解析、证据读取前后校验、浏览器会话读取。一个边界内的嵌套 `session()` 使用同一条连接，离开边界即关闭。没有跨请求池、身份缓存或保持事务快照。其他写接口仍使用原数据库路径及事务屏障。

连接仍由原 `Database.session()` 创建，保留 WAL、外键和等待设置；随后启用 `query_only`。SQLite authorizer 禁止 BEGIN/SAVEPOINT 和修改 PRAGMA，防止以后代码意外写入或保留旧事务快照。各 SELECT 都在 autocommit 下执行；在材料处理期间由另一连接提交的权限撤销、档案变化，后置查询必须立即看见并拒绝旧结果。版本、身份、授权和材料校验仍按原顺序执行。

复用对象限定创建它的线程与本次操作，不能跨 worker 或在操作退出后使用。正常结束、异常、取消都关闭连接；进入/离开每次读取检查总截止。底层同步 I/O 的协作取消边界保持原说明，12 秒预算和重试策略不变。

独立诊断在相同合成材料上，分别测网关会话、原页与片段检索，并发 1/4、每配置 30 波，共 450 样本。记录连接创建/关闭、SQL 类型、线程排队与实际函数执行时间；不记录 SQL 参数、身份或 Cookie。各阶段可能嵌套或并发，不能把阶段 P95 相加作为端到端耗时。

性能验收继续使用首批冻结的原始 900 样本矩阵及原有 P95 比值门槛。追加诊断用于确定原因和检查连接/SQL 数量，不替换原基线。真实网络与家庭设备仍需另行验证。

当前源码 profile 为 `reuse-runtime-study-read-connections-v1`，在原 95 文件候选上增加本说明及 `study_read_db.py`，共 97 文件；schema13、Tool1.2.1、OpenAPI76路径/44模型保持。旧 95 文件 `reuse-runtime-study-performance-v1` 单独验证与回退；不迁移或降级数据库。
