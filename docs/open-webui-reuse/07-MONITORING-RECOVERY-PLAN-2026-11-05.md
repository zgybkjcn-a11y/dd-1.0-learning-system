# W08 本地监控与 W09 完整恢复设计

日期 2026-11-05（本批从 11-04 跨日继续）。沿用目标 `https://172.19.116.53` 与原 HTTP53001 入口。前序[故障报告](../verification/reuse-fault-isolation-2026-11-04.md)保持；本批证据见[监控报告](../verification/reuse-monitoring-recovery-plan-2026-11-05.md)。

## 监控工具与权限

[采集器](../../scripts/collect_learning_monitor.py)只读取学习数据库中的固定聚合 SQL、公开 `/health`、文件系统可用容量及指定备份回执。SQL 使用 `mode=ro`、`query_only`、一个读取事务与查询截止，不读取账号、原卷、原答、provider 正文或凭据，不迁移数据库、不修改业务状态；仅支持当前 schema11。源库缺失/不可读、结构不支持或关键控制记录缺失时明确报警，不创建空库或报告正常。

**SQL 只读不等于文件系统只读。** API 关闭最后一个 SQLite 连接后，WAL/SHM 可能被移除。新隔离实测表明，全卷只读挂载会触发 `SQLITE_CANTOPEN`；失败报告保留。当前模板让采集器使用学习服务 UID10001，并允许该学习卷的文件系统写入，以便 SQLite 创建/维护辅助文件。未使用 `immutable=1`，因为它可能忽略正在使用的 WAL。脚本不发业务写语句，但容器持有该卷写权限，需在正式部署审阅中明确接受；若要求文件系统级只读，后续应提供专门的最小监控接口，不能静默忽略 WAL。

公开健康探测只允许显式端口的 `learning-api` 或 loopback，固定请求 `/health`，禁止代理与重定向，不携带 Cookie/密钥。HTTP 上限 2 秒/4096 字节，外层独立子进程 4 秒截止覆盖 DNS，退出后回收。数据库忙等待 1 秒，执行进度截止 2 秒；文件系统调用本身仍受宿主存储影响，监控失联由独立状态读取识别，不把这些数值称为全系统 SLA。

[可审阅 Compose 模板](../../deploy/open-webui-reuse/compose.monitor.template.yml)独立于应用 sidecar，使用显式 `monitoring` profile；固定已有学习镜像，容器根文件系统只读、capabilities 清空、无端口、无 Docker socket、无秘密挂载、只接已核验的 internal 网络。资源上限为 0.25 CPU、128 MiB、32 PID，日志最多 2×1 MiB。这些是本地保守配置，未证明正式容量。

模板需要显式指定镜像、采集器绝对路径、学习卷/网络、状态目录及回执目录；网络须事先核对 `Internal=true`。状态目录必须由 UID10001 持有、模式0700，文件0600；不会自动创建宿主 bind 来源目录。回执目录仅放聚合回执，并按该 UID 的读取需求设置权限。正式部署没有安装或启用本模板。

## 周期、告警与失联

采样完成后等待60秒；实际周期包括采样耗时，默认最多100万轮并不自动重启。每次先取得排他锁，第二个采集任务返回退出码3。默认队列超时300秒、待人工复核项超过100、剩余字节少于1 GiB或文件系统剩余空间少于10%、可用inode少于10000、备份回执过期24小时；均为开发阈值，正式值尚未冻结。

`latest.json` 是固定大小结构，使用同目录临时文件、fsync 与原子替换；不会无限追加历史。只保存固定告警码、时间、序号及新增/解除码。相同告警抑制重复事件，持续告警默认3600秒产生提醒；原始样本不写入日志。状态损坏和时钟倒退也会显示异常。退出码0表示本次无告警，2表示 attention，1表示执行失败；退出2不能当作容器崩溃。

示例（容器内；路径由显式挂载决定）：

```bash
python /opt/collect_learning_monitor.py collect \
  --db /learning/learning.db --storage /learning \
  --state-dir /monitor-state \
  --backup-receipt /backup-observation/latest.json \
  --cycles 1000000 --interval 60

python /opt/collect_learning_monitor.py status \
  --state-dir /monitor-state --stale-seconds 180
```

第二条可以由独立观察端运行；缺少心跳或超过180秒返回 `MONITOR_STALE` 与退出2。它不自动发送消息，正式接收人、值守、独立观察调度和通知仍未配置。不能只依赖采集器自己向自己报告存活。

磁盘检查使用 `statvfs` 的可用字节/inode，不递归读取附件、不写测试文件、不填满磁盘；Docker volume 常与宿主共用文件系统，此数值不是卷独享配额，也不证明附件写入或正式并发容量。

## 备份回执语义

指定回执格式为以下聚合对象；运行方应原子发布并限制写权限。`finished_at` 是 UTC Unix 秒，不使用示例时间作为真实记录：

```json
{
  "format": "dd-learning-backup-observation-v1",
  "scope": "learning_only",
  "status": "passed",
  "verified": true,
  "finished_at": 0
}
```

上述0是无效占位，不能让监控变绿。缺回执、失败、过期、未核验、未来时间或格式异常分别报告固定错误码；额外字段不进入输出。监控只是读取调用方声明，不自行执行备份、核验归档、恢复或签名。本批回执由合成夹具生成，验证的是状态转换，**没有新执行实际完整备份**。下一步应从真实备份/校验结果原子生成回执，并分别保留备份完成、归档校验、恢复演练三种证据；不能让任意 `verified=true` 替代恢复验证。

未知 provider 费用仍保留占用，监控不对账、不清零、不自动解除暂停。WebUI 聊天费用不在学习台账内；本工具始终输出 `chat_costs_covered=false` 和 `full_architecture_backup_covered=false`。

## 完整恢复组件与顺序

[机器计划模板](full-recovery-plan.template.json)固定七类必需组件，来源引用、责任人、保留策略、加密位置/密钥保管、维护窗口、RPO/RTO 和正式演练引用全部待填。模板不读取这些来源，也不授权执行。

| 组件 | 备份/恢复必须补齐的事实 |
| --- | --- |
| 学习数据库、附件、必要导出 | 核验API/worker及其他写进程已停；SQLite一致性备份、附件hash、schema与冻结业务对账；恢复撤销会话/上下文/挑战并暂停provider |
| WebUI数据库、上传、向量数据 | 先确认实际使用SQLite还是外部数据库、全部挂载与外部存储；单独协调聊天维护；不能只复制一个猜测的`webui.db` |
| 运行配置、Tools、身份绑定 | 固定镜像/源代码、网络/端口、Tool版本与分享/Valves/身份清单；秘密单独保存；重建后按固定ID核对网络与权限 |
| 秘密与证书 | 独立加密保管、恢复权限/UID、轮换策略、IP SAN/信任/有效期；不将明文秘密放入源码包/日志/公开manifest |
| 备份之后的删除记录 | 备份水位与持续删除日志；必须在恢复开放任何入口之前重放后续删除 |
| 备份之后的三通道费用 | 在途调用与费用水位、备份后账单来源；保留unknown及预留，不用旧快照抹去已发生支出 |
| 固定镜像、源码与依赖 | 归档hash、镜像digest、锁定依赖与离线恢复可用性；不隐式拉取latest |

当前 `restore_data()` 只重放恢复快照内已有删除记录；跨备份时点的删除/用量增量日志尚未在本批实现。不能以现有学习局部恢复承诺后续删除不会复活、外部费用不会遗漏。

维护顺序为：审阅窗口与备份水位 → 停用学习入口/Tools及三通道已授权dispatch → 排空或记录在途任务并停止worker/API → 经单独聊天维护停止WebUI写入 → 按固定ID核验退出与其他写进程 → 捕获七类组件/水位 → 校验归档与可恢复性。生产任一步均未执行。

恢复先在全新隔离空目标、外发关闭条件下核验归档和镜像，分别恢复配置/秘密与两套数据，在学习副本迁移并失效运行会话、重放删除增量、保留/对账费用，再核验附件、冻结成绩、身份与WebUI数据。最后验证网关/代理/网络/TLS及监控心跳，记录实际数据损失和耗时，由既定责任人按批准的RPO/RTO审阅后另行授权切换。

缺组件/hash不符、写进程未停/强杀未经一致性审查、缺删除或费用水位、恢复目标非空或已有新业务写入、秘密/信任不可用、业务/权限不一致时停止。保留原现场，不覆盖旧库，不凭换旧镜像宣称无损回退。本批只有可审阅设计，正式完整恢复、密钥保管和RPO/RTO仍未验收。
