## 3. P0：恢复并核对隔离运行环境

1. 仅针对两个指定隔离容器查看脱敏状态和必要日志，记录停止时间及可证实原因；没有证据时保留“原因未知”。不打印完整环境变量、Valves 或密钥，不读取正式 WebUI 密钥库。
2. 固定工作区候选源码与必要文件的内容指纹，注明包含未提交改动；记录实际 Open WebUI 版本、镜像 ID/digest、学习服务 schema 和适配器内容指纹。不要将 `:main` 标签当作固定版本，也不要以重新拉取最新镜像替代现有 0.12.5 基线。
3. 若需读取或迁移旧隔离数据，先在独立目录/卷制作可核验副本；不让新旧程序写同一数据库。优先以当前源码在新 disposable project/独立卷准备候选环境，保留原隔离卷。
4. 使用 `docker-compose.learning.yml` 和现有静态 preflight 核对隔离配置；启动前核对实际挂载、端口、网络、身份与 provider 默认值。学习 API 只通过隔离网络访问；如需浏览器入口，限制为 loopback/受控代理，不能暴露可伪造身份的公开入口。
5. 用合成身份检查 health、schema revision 7、生产模式 bootstrap 不可用、无受信上下文拒绝、跨学习者拒绝。检查与当前 OpenAPI/Tools 契约的兼容性；静态检查通过不等于运行时出网限制已经验证。
6. 核对隔离实例中 Tool 内容与当前源码差异；有差异时仅更新隔离记录并复验相关 loader/签名契约。已完成注册不是从零重做的任务，但旧注册记录不能证明当前版本一致。

交付：隔离运行准备报告，包含版本/指纹、project/卷/网络、边界检查、备份位置、启动/停止方式与未解问题。通过标准：环境可复现、隔离边界明确、API 和受信身份可用，不涉及真实 provider 或生产副作用。P0 通过不提升真实模型/回调验收状态。

## 4. P1：真实模型 tool call 与最终可信 UI 回调

输入：测试模型名称和可调用连接、运行位置、原生 tool calling 支持情况、测试账号与两个合成学习者、可信浏览器入口。优先使用已有自托管/本地测试模型；若使用外部模型，先明确预算、重试上限、出网 endpoint 和只可使用的合成资料。当前禁止真实 API 的限制未改变前不执行模型调用。

1. 在真实聊天页用模型发起 `list_learners`/进度等读取，证明工具调用来自实际模型响应，宿主身份/UserValves 来自受信上下文。不能用直接调用 Python 方法、伪造 tool call 或 harness 回调替代这一证据。
2. 核对上传/今日任务/错题本/开始测验的入口是否真正可达。已有独立 `/ui` 的能力不能自动算作 Open WebUI 入口；如仍需链接或工作台承载，明确承载方式和身份校验，缺失入口先实现并验证。
3. 用代表性合成资料完成上传 → 分析候选 → 查看原页/人工证据 → 原生确认 → 错题本；另用已审核题目和独立测验上下文验证原生输入 → 服务端判分 → 反馈/调度。这里验证真实组件连接，不重复四格式数据库持久化基线，也不宣称 OCR 质量。
4. 覆盖 `confirm_import`、`confirm_learning`、`confirm_draft_interactively` 别名、`submit_answer`。在浏览器显示服务端权威原文，只有用户接受最终回调后才创建并消费挑战；普通聊天文字不能冒充最终确认或原始答案。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 接受确认/提交原始答案 | revision/身份绑定正确，业务结果至多生效一次；原始输入按服务端约定保真 |
| 用户取消、关闭弹窗、非肯定/错误回调 | 不创建最终 challenge，不写成成功 |
| 真实浏览器 callback 超时 | 达到声明的 120 秒等待上限后 fail closed，无最终确认/答案写入；不通过模拟时间冒充浏览器超时 |
| 断线/刷新后重进 | 从服务端恢复真实状态，重新读取 revision；不能把已失效回调当作接受或重复提交 |
| 回调前资源修订/取消 | 旧版本提交被拒绝，迟到动作不写成功 |
| 同请求重试/挑战重放 | 无重复错题来源、成绩或调度；异载荷冲突显式返回 |
| 跨学习者/伪造宿主参数 | 读取与写入均拒绝，模型不能改变受信 subject/learner 或权限 |
| 提示后、普通练习模式 | 辅助资格有服务端证据，不按独立掌握晋阶 |
| Agent 请求最终操作/超出允许范围 | 只返回受信 UI handoff 或明确失败，不自行批准、判分、消费挑战 |
| 模型可见结果与测前客户端 | 不泄露答案键、challenge/nonce、原始答案或确认集合；日志证据使用合成标记并脱敏 |

交付：真实浏览器报告、截图/录屏摘要、模型/宿主事件 ID、API 事件与数据库结果对账、异常矩阵、发现缺陷及聚焦复验记录。通过标准：实际模型产生调用、真人操作原生回调、成功与异常场景均有可关联证据。资料仍为合成，T04/T05 学科质量门槛保留；T03/T16/T18/T20 只根据各任务的完整验收范围逐项更新。

## 5. P2：脱敏资料与人工参考标注

输入由资料提供者和人工审核人准备，工程侧提供格式及校验流程。先固定首批支持学科/题型；不扩展到全学科自动判分。建议首批从 5–10 份、约 20–40 页资料开始估算工作量，实际数量由可用资料和题型覆盖决定；这不是统计显著性或准确率承诺。

1. 完成去标识化与使用范围检查，建立文件 hash、文档/页 ID、来源与审核记录，排除姓名、班级、账号等不必要信息。去标识化本身不自动授予外发许可。
2. 逐题标注题号/小问、原始转写、区域坐标、跨页关联、学生作答、教师证据、参考答案及版本、定义域/单位、五类参考判定与审核人。不知道的字段明确标未知，不用模型补造。
3. 覆盖多页、小问/跨页、模糊/符号/笔迹、红笔批注、未作答、部分错误、答案版本冲突及首批题型；缺少某类就记录未覆盖。
4. 按文档和母题拆分开发集/冻结验收集，关联资料不跨集合。预先确定区域匹配、漏题、文本错误、判定、弃判的统计口径、分母和可接受阈值；由审核人确认后评估，不能测完再调门槛。

交付：脱敏文件清单、标注数据、覆盖表、集合拆分、指标规则和人工审核记录。T04 只有必要资料/审核与规则齐备才能解除对应阻塞；建议规模不足时不能伪称全部题型或真实质量已覆盖。

## 6. P3：独立 staging 的真实 provider 受控冒烟

输入：明确 provider/版本/endpoint、独立运行时凭据来源、最大调用次数/费用、超时/重试上限、允许的测试资料和真实调用许可。密钥通过运行时注入，不写入仓库、公开文档或日志。保持默认配置和共享环境外发关闭，仅获准 staging 使用临时明确配置。

1. 先核对外发边界和安全降级是否具备，确保调用计数/重试可以限制；如缺少预算控制或对账能力，先补本地实现，再发真实请求。
2. 以合成图片做最小 Tencent `QuestionSplitOCR` 冒烟，记录 RequestId、provider/参数版本、耗时、状态和调用次数；页面与候选仍需人工复核，不自动确认。
3. 在独立环境验证安全错误、超时/连接失败、限额停止和失败后的重试恢复。优先用受控网络故障验证错误路径，不为了制造故障新增无意义付费调用。
4. 首发包含诊断/变式模型时，先补真实 provider 适配器本地实现：当前工厂只支持 mock，其他配置返回 UnconfiguredProvider；补目标协议、配置、schema/引用校验、超时与安全降级的合成响应回归。实际连接获准后再受控实测，保留 `needs_review`；OCR 一次成功不能证明这些模型能力通过。
5. 费用以真实账单或 provider 可核实计费记录对账，账单未取得时明确标待核实；调用前的预算上限必须已经确定，不用估算费用充当实际费用证据。

交付：脱敏调用/费用记录、真实成功与失败证据、候选对账和降级报告。T05 按实际验收范围更新；仅冒烟通过不等于脱敏整卷质量通过，也不改变生产/真实资料外发授权。

## 7. P4：整卷质量、诊断/变式和真实资料生命周期

1. 在已获准的数据与 provider 范围内评估冻结验收集。所有页和题计入统计；列出输入/成功/失败页、题数、漏题/多题、文本错误、符号和区域偏差、五类判定混淆、精确率/召回率、弃判/待复核、耗时与实际费用。分母为零或资料缺失时标不可计算，不写 100%。
2. 对照人工参考检查答案版本、单位/定义域和冲突路由。失败页和不支持题型可见；模糊、红笔或高置信度不能替代充分证据。只评价当前实际实现的判定能力，不把人工判断归为自动模型正确。
3. T12 逐条回查原件、区域、人工 judgment、确认版本与错题内容；在独立数据副本演练重复导入、撤回、后续来源保留、导出/删除与恢复。受控重放属于操作测试；真实再错/真实学习行为证据缺失时继续保留该 unmet 项。
4. T13 由人工抽检诊断引用是否存在、缺步骤是否被补造、证据变化是否使旧诊断失效、provider 失败是否保留错题及待复核状态。
5. T14 以已审核母题和首批支持领域抽检变式：条件完整、定义域/单位、可解性、答案、超纲及与母题约束。未审核/失败变式不能投放独立测验。
6. 将失败项分为程序缺陷、provider 能力限制、资料/标注争议与未支持题型，逐项修复或如实限制。仅对相关变化复跑聚焦测试，必要时执行完整回归；不通过删断言、弃掉失败样本或修改验收集制造通过。

交付：质量报告、人工裁决/变式审核、错题生命周期对账、缺陷与未覆盖清单。通过标准：预先固定的验收规则有实测依据；未满足规则和任务子项继续保持 partial/implemented/blocked，不因局部指标好看整项 verified。

## 8. P5：故障、版本兼容与一致性恢复

1. 先明确适用系统：当前为 SQLite 和本地附件。外部数据库服务、对象存储并未因此获得覆盖；若后续目标确实使用它们，需先明确接入契约与独立演练环境。若决定不纳入本轮，需明确范围决策并同步任务/QA，不能自行标“不适用”降低原验收门槛，也不为勾选测试无故引入新架构。
2. 保留已完成 SQLite writer/provider 进程中断、lease 重领、迁移原子性与备份篡改拒绝证据。没有相关变更时不重做；新增模型/存储连接或恢复变化针对其真实边界补证。
3. 对适用外部连接演练连接中断、超时、恢复和迟到结果；检查状态可恢复、任务不写假成功、原件/来源不重复、成绩与调度至多生效一次。涉及付费 provider 仍受 P3 范围和预算控制。
4. 固定 Open WebUI 0.12.5 基线和后续明确目标版本，记录 Learning API/schema、Tool 内容和模型调用模式组成的版本矩阵。未明确升级目标时不自动追随 `:main`。
5. 在独立副本做组合备份/恢复：数据库、附件/原页、候选与确认版本、错题、学习事件、卡片/成绩、配置及安全提供的凭据引用作为一致集合；恢复后检查完整性与业务结果。不得让新旧程序写同一迁移库，也不得在开放写入后覆盖旧快照并声称无数据损失。

交付：适用故障矩阵、版本矩阵、备份 manifest/校验结果、恢复对账、已知限制和恢复操作说明。通过标准：每个要求的系统有真实可关联证据；当前未具备的外部数据库/对象存储/provider 故障仍准确保留。

## 9. P6/P7：试用准入与真实观察
