# 主规划与升级方案二次复审记录

本轮覆盖上述两份规划及其相互依赖。只修订文档，未开发、升级、停机、修改配置或写业务库。本文记录发现与修订状态，不替代主规划的需求/接口定义或升级文档的操作流程。

## 1. 结论

总体架构方向可保留，但原文还不宜直接作为完整开发验收规格。复审发现 **12 项问题：3 项实施阻断、7 项高优先级、2 项中优先级**。已将明确的规则和边界修订到两份 R2 文档。

“已修订”仅表示文档缺口已补；身份与原生交互、模型连接、备份恢复等 **G0 实测门槛尚未执行**。当前可以进入 P0 做受控验证；不能据此宣称学习系统已完成、已兼容升级或已安全上线。

## 2. 按严重性排序的发现

### R01｜实施阻断：工具与敏感内部命令没有分开

**原位置**：主规划第 8 节，把 `confirm_question_draft`、`submit_answer` 与模型可用查询工具并列；第 4.2 节虽要求可信 UI，未在接口层强制。

**影响**：模型可转述或编造学生答案/确认。即使不能直接传 `is_correct`，也可能用模型自己算出的答案代替真实学生作答，污染掌握度。

**修订**：区分允许清单工具、交互编排和服务内部命令。最终确认/提交不暴露给模型，只能通过绑定身份、题目版本、操作和 nonce 的挑战，经受信 UI 回调消费。

**待验收**：伪造确认、模型直接提交答案、过期挑战、不同学习者复用挑战、重复提交必须拒绝或幂等；不依赖 system prompt 来保护这些命令。

### R02｜实施阻断：缺少 UI 取消、超时、断线的严格语义

**证据**：本轮只读检查运行容器 `open_webui/socket/main.py` 的 `get_event_call`。当前代码在连接中断或超时时返回包含 `error` 的非空字典；官方事件文档也明确异常返回结构。

**影响**：若实现时使用简单 `if response`，错误对象可能被当作用户同意。这是规划留下的实现风险，并不是已经发现运行中的学习插件存在该漏洞；学习插件尚未开发。

**修订**：严格解析允许的成功结构，明确取消/错误/未知格式不写有效成绩；过期与重复挑战拒绝，取消可恢复会话。P0 必须测当前模型调用模式中的真实交互。

**待验收**：非空错误字典、`None`、取消、空输入、错误会话、超时、断线重连均不能自动确认。

### R03｜实施阻断：两份文档接入方式不一致，后备页面没有鉴权设计

**原位置**：主规划偏向原生 Tools，升级方案又倾向外部 OpenAPI；原生交互失败就切换独立页面，但没有说明页面如何识别当前学生、提交答案和撤销会话。

**影响**：开发可能并行实现两套路径，或以携带管理员令牌的链接拼出后备页面；估算和验收也失去唯一基准。

**修订**：v1 统一为薄原生 Tools → 内部 `/api/v1`。外部 OpenAPI 工具连接后置。后备页面必须另做一次性引导凭据到会话的兑换、过期/撤销和写请求保护，并先重估工期。

**待验收**：G0 通过才继续正式测验接入；未通过可继续独立数据/调度开发，但正式测验保持关闭。

### R04｜高：调度还不是完整状态机

**原位置**：主规划第 6 节没有定义维护期的下一日期；“每个复习窗口一次”未给窗口标识；stage 5 前一天提示后答对是否毕业不明确；错误标签与判分可信度混在一起。

**影响**：不同实现会得到不同复习日期，重复尝试可能多次晋阶，短期提示可能被算成长期掌握。

**修订**：补充 `cycle_id`、卡片 revision、到期时刻、stage 转移、维护 30 天、提示分流、过期提交及替代题规则。v1 可信独立答错仅目标卡再学习；按 AI 错因标签细分调度后置，避免不稳定归因直接改阶段。

**待验收**：可控时钟覆盖 2026-11-02 → 12-31 → 2027-01-30。按无中断示例，首轮约 59 天，第一次维护复查约 89 天；7~14 天试用只能观察可用性与初期趋势，模拟测试不代表学习效果。

### R05｜高：SQLite＋worker 缺少可靠提交和恢复约定

**原位置**：主规划提到作业表与独立 worker，但没有原子领取、租约、迟到结果、调用过程中事务边界和人工改分重放规则。

**影响**：超时重试可能重复生成、重复计费或覆盖新结果；把模型调用放进数据库写事务会拖长锁持有时间；改分可能只改分数而留下错误调度。

**修订**：原始提交先保存 pending；外部调用在事务外；最终判分与调度短事务原子应用。作业使用租约、输入版本、有限重试和结果去重；迟到 worker 不能提交过期结果。历史修订用补偿事件并按冻结规则重算。

**待验收**：worker 崩溃、重复领取、租约过期、并发答案、相同幂等键不同负载、模型完成但写入失败、人工改分后重算。

### R06｜高：身份和授权在升级/恢复后的归属不完整

**原位置**：已有 `learner_access`，但 WebUI user ID 与业务账号关系、账号删除重建和管理角色边界未明确。

**影响**：恢复旧 WebUI 或重建同名账号时，可能错误认领学习档案；模型可见参数也可能被误用为授权来源。

**修订**：增加稳定业务账号与 `provider/issuer/subject` 映射，明确监护人/学生/内容审核权限。授权只能经受控管理入口建立，不能按邮箱同名自动归并；未知映射默认拒绝。

**待验收**：相同邮箱的新 subject 不继承旧数据；切换学生作废旧挑战；恢复后未知身份不得获得档案访问权。

### R07｜高：不返回标准答案仍不足以证明无提示测验

**原位置**：主规划强调工具输出不能包含答案，但普通聊天历史、RAG、诊断工具和模型自己生成的解答仍可能影响学生。

**影响**：一次有答案上下文的答对被计为独立掌握，图表出现虚假提升。

**修订**：先获取原始作答，再返回教学反馈；活动测验期间相关诊断/解析访问由服务门禁或先记辅助；辅助情况不明只作练习。不把系统内无提示指标宣传为监考/作弊识别。

**待验收**：学生在测验中请求历史诊断、提示或解析时，独立评分资格正确变化；模型侧拿不到标准答案端点。

### R08｜高：演练副本的隔离顺序仍有漏洞

**原位置**：升级方案虽要求禁止外发，但“禁用克隆配置”的执行时点与方式不清；可能先启动再到界面关闭任务，也可能只改环境变量而保留数据库里的正式连接。

**影响**：副本可能一启动就使用正式凭据调用真实服务，或连接正式学习库。

**修订**：第一次启动前网络出口默认拒绝、隔离正式网络/挂载；在该状态下清理持久化任务与连接，再按目标逐项放行测试凭据。要求证明隔离，而不是仅改变环境名或端口。

**待验收**：副本对正式 API、通知目标和真实模型请求默认被拒绝；解析出的挂载路径没有正式目录；不能用 `.env` 修改代替持久化配置检查。

### R09｜高：备份集合写了原始教材清单，遗漏原件的明确位置

**原位置**：升级方案第 5.1 节列“原始教材清单”，但前文要求原件可重建，本机教材又在相邻 `textbooks/`，不完全位于 Open WebUI 目录内。

**影响**：只备份项目目录可能无法恢复全部原始教材；哈希清单只能证明缺文件，不能还原文件。

**修订**：明确原始教材文件＋哈希清单；若在已有独立备份中，必须记录不可变快照并验证恢复。完整 WebUI data、学习库/附件、配置和密钥继续纳入。

**待验收**：隔离恢复实际打开代表性原图/PDF、关联与检索；备份校验和正确不等于业务恢复成功。

### R10｜高：回退范围相互矛盾，增量重放被说得过于容易

**原位置**：主规划笼统要求停掉学习服务回退，升级方案要求尽量保留未改变的学习服务；同时提到增量导出/重放，却没有经过验证的跨版本工具。

**影响**：WebUI 升级故障可能连带回退正常学习数据；开放写入后恢复旧库容易丢新记录，甚至出现身份与附件悬空。

**修订**：区分首次学习服务发布回退与单独 WebUI 升级回退。开放写入后的增量保护明确为待选择的恢复流程，不承诺现成自动无损重放；增加学习库自己的迁移约束。正式切换还要求关闭真实入口、确认无写入者、仅受限验收访问。

**待验收**：演练 B0 与正式 B1 不混用；保留兼容学习服务时核对身份和引用；没有已验证重放路径时，不声称恢复旧库可以保留全部新增数据。

### R11｜中：资料导出、删除和备份过期没有完整生命周期

**原位置**：规划强调历史保留和审计，但未定义原图/日志保留策略，也没有考虑已删除资料从备份恢复后再次出现。

**影响**：用户无法完整管理自己的学习资料，删除与备份策略相互冲突。

**修订**：P0 明确保留期限；授权导出、软删除与物理清理分层，记录备份到期规则和恢复后的删除重放；日志不默认保存题图/全对话，不以审计为由永久保留原文。

**待验收**：无权账号不能导出/删除；删除不会连带其他学习者；恢复流程尊重已经执行的删除。具体保留天数须在实施时按实际用途确认，本次不虚构用户偏好。

### R12｜中：工期与实际范围不匹配，兼容工作重复计数风险

**原位置**：主规划 8~12 人日后另加升级保障 2~3 人日，但可信交互、作业恢复、改分与入口隔离尚未明确纳入。

**影响**：看似详细的交付物无法按同一范围估算，后备页面一旦启用会继续扩大范围。

**修订**：统一为 P0 2~3、P1 3~5、P2 3~5、P3 3~4 人日，即试用版 11~17 人日；加 P4 1~2 人日为 12~19 人日，另加 7~14 天观察。已经包含升级演练，不再重复加 2~3 人日。P0 后重估，后备页面不在当前估算内。
