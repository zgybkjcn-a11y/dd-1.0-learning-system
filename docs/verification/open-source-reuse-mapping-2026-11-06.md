## 代码里值得借鉴与需要调整的地方

1. **把知识内容与题目分开组织**：`Concept` 的 `conceptType`、`misconceptions`、`masteryCriteria` 可以分别支持概念说明、错因提示和可观察目标。题目与标准答案继续走本项目独立审核；“概念已存在”不取得出题/判分资格。
2. **版本绑定的覆盖关系**：采用 `covered_by` 表达概念落在哪本书、哪章/节，保留来源和定位精度。一个概念只有一个 canonical `sourceRef`，却可能有多个覆盖位置，不能只用 sourceRef 的年级/路径过滤所有出现位置。
3. **先修图作参考**：小样本可展示“有理数减法 → 有理数加法 → 相反数 / 绝对值”的两跳关系；这是上游标为 audited 的结构预览，不是本地审核或学生能力测量。后续结合本地正确/错误/提示记录解释学习建议，不能把关系边当晋级标准。
4. **不能直接照搬通用查询方法**：`tools/kg/src/query.ts` 的 `prerequisitesOf()` 只筛类型/方向，未筛 `reviewed`；README/关系 schema 却要求先修闭包只走 audited。适配时明确筛选审核档、限制深度/节点数并保持 hard/soft，不假设所有上游路径都执行了同样过滤。本次没有执行该代码。
5. **以固定源码为准**：`runtime_view.ts` 的实际 `EDGE_FIELDS` 包含 `strength`，相邻注释仍说不保留。消费方核对具体版本的字段契约，不用旧注释/README 推断运行时丢失或存在什么字段。
6. **保留审计门槛**：借鉴唯一 ID、引用完整性、先修无环和未知偏移不默认为 0 的思想；再补本项目的 PDF 哈希、逐页转写审核、独立内容审核、题目审核与学生档案隔离。
