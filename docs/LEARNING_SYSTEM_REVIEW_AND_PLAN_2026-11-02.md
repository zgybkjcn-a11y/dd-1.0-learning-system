## 1. 历史运行核验结果（公开摘要）

### 1.1 已确认的事实

公开版不包含原始运行快照、个人资料、教材清单、实例配置、文件库存、访问地址或镜像摘要。历史核验确认当时存在 Open WebUI 运行实例；其余实例级证据保留在本地，不作为公开项目的交付材料。公开的脱敏摘要见同目录 `AUDIT_BASELINE_2026-11-02.json`。

### 1.2 不能据此宣称已经可用的能力

- 模型配置里出现某个名称，不证明上游模型身份、连接可用性或工具调用可靠性；本轮没有发送付费模型请求。
- 教材状态为 `completed`、有抽取文本，不证明公式、图形、页码、教材版本或检索结果正确。
- 尚无错题、答题事件、调度状态、诊断版本、掌握证据等学习业务数据结构。
- 已有绘图工具可以继续用于讲解，但不能替代结构化知识点关系或掌握状态。
- 尚未做恢复演练、真实用户验收或学习效果验证。

### 1.3 先处理的工程问题

1. **凭证治理**：Compose 中存在明文应用密钥，教材脚本中存在硬编码会话凭证。文档不记录其值。实施时将凭证移至受限配置，撤销或轮换已暴露会话；应用密钥不能直接随意重置，应先核对当前版本影响及回退方式。
2. **固定运行基线**：实施前保存当前镜像 digest、配置与一致性数据备份；不要把“升级 Open WebUI”和“开发学习系统”合并成一次不可归因的变更。
3. **教材脚本修复**：当前轮询检查 `processed`，实际文件成功状态为 `completed`；“只要有 content 就成功”的判断也不充分。应按当前接口状态处理成功、失败和超时。
4. **导入结果可信**：脚本没有严格验证 HTTP 状态及挂接结果，可能输出虚假的成功信息；需加入结构化错误、重试上限、文件哈希去重、断点续传和关联校验。
5. **调用安全**：替换拼接字符串加 `shell=True` 的 HTTP 调用，使用 HTTP 客户端或参数数组；日志不打印凭证。
6. **版本与质量**：确认教材版次、学期和适用课程目录；先抽查数学公式、符号、图形和页码，再决定是否升级 OCR 或 embedding。更换 embedding 必须重建相关索引并比较前后结果。

## 3. 优化后的产品边界

### 3.1 第一版必须形成的闭环

1. **学**：记录今日新学知识点、教材版本和简短自测；没有错题也能加入复习。
2. **练**：录入文字、单题图片或整份试卷/作业的多图/PDF，保留原件、学生原作答和步骤；自动分题、识别批改或匹配参考答案，形成可复核草稿。
3. **错**：自动收集疑似错题与部分错误小问，经可信界面批量确认后正式入库，关联来源和稳定知识点 ID；无法判定单列复核，重复提交不重复建档。
4. **析**：给出有证据的错因假设、正确解法依据、补救练习；缺信息就追问。
5. **测**：生成到期队列，进行独立变式抽测，服务端判分并写入答题事件。
6. **反馈**：更新复习时间与掌握证据，输出今日完成量、待复核量和薄弱点。

### 3.2 首期范围与默认值

- **试点学科**：七年级数学，先选当前已导入上册中的 2~3 个章节。此为降低验证范围的建议，不意味着现有其他学科被删除。
- **学生上下文**：数据结构从第一版支持多个学习者；试点先绑定一个明确档案验证流程。若同一监护人管理多个档案，切换必须显式确认，并绑定会话。
- **每日预算**：建议初始 15~20 分钟、5~8 项，均可配置；以实际试用用时修订，不写死成教学标准。
- **主要入口**：Open WebUI 专属模型“学习教练”与原生 Tools 交互；在 P0 先验证可信输入、取消/超时与恢复链路。独立答题页面是验证失败后的替代方案，届时先补身份会话设计并重估，不能视为已有入口。
- **输入**：文字、清晰单题图片，以及整份已批改试卷/作业的多图与 PDF；有适配答案的未批改材料纳入受支持题型。自动分题和判错后支持批量确认，复杂手写推导、几何图形、跨页不完整和判定冲突进入复核。整份上传是 U1 新增必需范围，不能继续只按单题录入验收。
- **图表**：第一版交付薄弱点表、阶段分布、趋势；完整知识图谱与独立家长门户后置。
- **提醒**：第一版保证“打开学习入口可查今日任务”；站外推送单独列入下一阶段，并由用户选择渠道与接收人。

### 3.3 试卷与作业导入（U1 新增）

完整流程为：选择学习者 → 上传多图/PDF及可选参考答案 → 质量检查/分题 → 分离原题、学生作答与教师批改 → 自动形成候选 → 批量确认正式入库 → 归因与复习。已批改材料依据可定位的批改证据；未批改材料需匹配答案与支持题型的验证，不能只凭模型自评判错。

保留正确、错误、部分错误、未作答、无法判定五类结果；待确认收集箱与正式错题本区分，未作答可转待补做。正式错题保留来源页码/区域和原始作答；错误按小问记录，完整大题背景仍可查看。导入观察不等于系统内独立评测，不直接重置已有复习阶段。

本模块优先于扩展动画库与视频导出；U0–U3 为完整试用必需，U4 的规则化自动入库与复杂题型后置。接口、数据约束和验收详见 `PAPER_HOMEWORK_IMPORT_DESIGN.md`，本轮仅补充设计，尚未实现服务。

## 4. 技术架构与集成决策

```text
学习者 / 监护人
       │
       ▼
Open WebUI 0.12.5
  ├─ 学习教练模型：教学对话、解释、工具选择
  ├─ 原有教材知识库：经版本/页码核对的参考资料
  └─ 薄 Tools 适配层：注入可信账号身份、调用业务 API
                    │ 服务认证 + 可信身份上下文
                    ▼
            Learning Service（FastAPI）
              ├─ 学习者授权与会话归属
              ├─ 试卷/作业导入、分题、错题收集与复核
              ├─ 题目草稿、错因诊断、人工复核
              ├─ 任务编排与确定性复习调度
              ├─ 变式生成、校验、测验与判分
              └─ 指标、审计、后台作业
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
     learning.db  附件存储  模型/检索适配器
     独立 SQLite           有版本、超时、重试、成本记录
```

### 4.1 为什么采用该结构

- **业务服务独立**：学习状态和调度由程序确定，不让大模型直接决定数据库状态；便于单元测试、迁移和恢复。
- **独立数据库**：开发 `learning.db`，不向 `webui.db` 添加业务表或直接修改其内部配置。初期单实例写入可用 SQLite WAL；迁移到多副本或更高并发时再评估 PostgreSQL。
- **Tools 保持轻量**：Python Tools 使用当前版本提供的 `__user__` 等服务端上下文。插件不实现调度算法、不保存上游密钥、不直接拼 SQL。
- **确认交互是 P0 阻断门槛**：验证 `__event_call__` 在本机模型调用模式中的输入/确认行为，覆盖真实输入、取消、超时、断线和重试。只有适配器从已验证的 UI 回调收到匹配挑战的明确成功结果，才能提交确认或答案；错误、未知格式和缺字段均不得视为同意。不能用 `if result` 判断确认成功，当前版本会返回非空错误对象。
- **唯一首期接入方式**：v1 使用薄原生 Tools 适配器；FastAPI 的 `/api/v1` OpenAPI 文档作为内部契约，不直接整体暴露给模型。外部 OpenAPI 工具连接列为后续选项，先证明身份与交互等价再迁移；不在首期维护两套调用路径。
- **Functions 非必需**：除非确需 Pipe、Filter、Action 扩展交互，否则不用 Functions 承载核心逻辑。不能假设“函数调用”就是 Open WebUI Functions。
- **无须首期增加 Redis、Celery、图数据库或新向量平台**：长任务先用持久化作业表与单独 worker；扩展依据实际任务量决定。

### 4.2 身份、隔离与测验保密

- `__user__` 的账号 ID来自 Open WebUI 服务端，不能让模型在参数中自行指定任意用户 ID。
- 服务层校验账号对 `learner_id` 的访问权限；查题、导出、附件、诊断、测验和统计都须过滤学习者范围。
- 若同一账号有多个学习者，当前学习者由明确选择绑定到会话；不能靠模型从“二年级”“七年级”称呼猜测。
- 适配层通过内部网络和独立服务凭据调用业务服务；身份头只表示身份，**不能单独当作认证**。未授权请求即使伪造身份头也应被拒绝。
- 外部 OpenAPI 方案若启用，用单连接定制身份头及认证；不要为了一个服务将姓名、邮箱等信息向所有工具全局转发。
- `start_test` 只返回题目、允许的提示与会话 ID。标准答案、评分规则、模型内部分析不进入学生侧工具输出、流式事件或客户端可读元数据。
- 提示请求显式记为 `hint_used=true`；测验中展示了答案则记为 `answer_exposed=true`，该次不算独立掌握证据。
- 结构化确认与作答应直接由 UI 回调或经过认证的页面提交并与测验项绑定；模型转述“用户已确认/已作答”不能充当可信回调。纯聊天转录先作为待确认草稿，避免模型改写学生答案后造成错误判分。
- 学生普通账号只保留必要权限；管理员账号用于管理。教材/学生输入均作为数据，不能覆盖系统指令或调用任意系统工具。

### 4.3 确认、账号与模型调用边界（R2 新增）

- **账号与档案分开**：`identity_bindings(provider, issuer, subject) → account_id` 映射到学习服务自己的稳定账号 ID，再经 `learner_access` 授权。Open WebUI user ID 只是外部 subject，邮箱/姓名不得用于自动合并；删除并重建账号不得自动继承旧学习记录。
- **最小角色**：监护人管理自己被授权的学习者，学生仅提交自己的学习/答题数据，内容审核者确认题目与评分依据。首次授权由管理员在受控配置/管理入口建立，聊天模型不能创建授权或自行提升角色。
- **先有挑战、后有确认**：服务创建短期有效的交互挑战，绑定账号、学习者、操作、题目/草稿版本、测验项和一次性 nonce；受信适配器收到严格校验过的 UI 回调后，以独立凭据向非模型接口提交原始结果。回调字段不得覆盖服务端绑定的身份和资源。
- **原始答案保真**：存储 UI 原始文本；需要数学规范化时另存规范化值及规则版本，不覆盖原文。取消/超时可以保留草稿或暂停会话，但不创建有效成绩、不晋阶。
- **恢复与切换**：交互挑战过期或已消费则拒绝重放；切换学习者使旧挑战失效。恢复测验时从服务取同一冻结题目版本，重新鉴权并签发新挑战，不从模型对话恢复授权。
- **独立页面不是免鉴权捷径**：若需要后备页面，必须新增并验收短期一次性引导凭据到服务会话的兑换、过期、退出/撤销、写请求保护与严格来源策略；禁止把 WebUI 管理员密钥、长期服务令牌或登录令牌放进链接。未完成时只保留查询/教学功能，不能宣称正式抽测闭环上线。
- **独立的模型调用**：业务服务使用显式配置的模型连接，不读取 WebUI 密钥库；不把本服务所绑定的学习教练再当上游模型调用，防止递归工具循环。P0 验证一次真实结构化生成及失败路径，模型别名存在不等于接口可用。
- **费用与数据外发**：启用前配置调用上限、超时和单作业重试次数；无额度或连续异常时暂停自动生成，已验证题库与查询仍可用。日志隐藏密钥与原始个人信息，图片发往外部模型/OCR 的范围写入可见说明并由实际使用方确认。

### 4.4 模型与检索

- 第一版模型生成结构化诊断/候选题，经过 schema 校验后入库；请求保存模型配置 ID、提示词版本与结果版本。
- 模型超时或不合规 JSON 不应产生“已诊断/已判对”的状态；作业可以重试，终止后显示可恢复错误。
- 上游模型连接需显式配置与验证，不从 `webui.db` 私自抽取密钥，不假设现有模型别名对应官方型号。
- 教材检索结果应包含知识点、教材版次、章节、页码/定位和片段 ID；找不到证据时明确标为未检索到，不补造引用。
- 首期可通过已配置知识库辅助教学；服务端权威题目生成使用审核过的章节材料或经验证的检索适配接口。Open WebUI 对话 RAG 不自动等于独立服务能安全访问同一检索结果。
- 检索质量先做小型评测集，再决定是否调整切块、混合检索、中文/多语 embedding、reranker；调整后保留对照结果与可回退索引。

## 5. 最小数据模型

原题、答案、诊断、学习状态不能全部压在一张错题表内。建议以下业务实体，所有表使用稳定主键、UTC 时间和迁移版本。

| 实体 | 核心字段 / 约束 |
| --- | --- |
| `learners`、`learner_access` | 学习者 ID、年级、时区、账号授权关系；不以年级或模型名称当身份 |
| `accounts`、`identity_bindings`、`interaction_challenges` | 稳定业务账号、外部身份 issuer/subject、资源绑定的一次性交互挑战；授权不依赖邮箱或模型参数 |
| `knowledge_points` | 学科、年级、教材版次、章节、稳定知识点编码、父节点/先修关系 |
| `learning_items`、`learning_events` | 学习对象、来源（新学/错题）、学习时间、完成方式；支持没有错题的正常学习 |
| `questions`、`question_versions` | 原题文本、标准答案独立字段、题型、附件引用、版本、知识点关系、来源、审核状态 |
| `source_documents`、`source_pages`、`import_batches`、`import_runs` | U1：原卷/答案文件、自有附件引用、学习者、页序、哈希、批次与处理版本；与已有 `jobs` 配合 |
| `import_items`、`source_regions`、`answer_key_mappings`、`import_judgments` | U1：题号/小问、跨页区域、原题/学生作答/批改分离、答案版本映射、判定依据与复核状态 |
| `mistake_entries`、`mistake_sources` | U1：正式错题、错误发生来源、原作答与区域引用、确认/策略版本、诊断/撤回状态；去重不吞并真实再错 |
| `diagnoses` | 学生答案和步骤引用、错因多标签、证据定位、待确认项、补救建议、诊断状态、模型/提示词版本 |
| `review_cards` | 学习者 + 学习目标、规则版本、阶段、到期时间、上次有效评测、维护状态；区分原题与知识点，不让变式各自重复计成独立掌握 |
| `test_sessions`、`test_items` | 学习者、关联复习卡、模式、冻结题目版本、隐藏答案/评分依据、会话状态、过期时间 |
| `attempts` | 实际作答、耗时、提示/答案暴露、得分与规则、判分状态、人工修订、幂等键；保留所有真实尝试。U1 导入观察标记 `source=uploaded_work`、`assessment_eligibility=false`，不冒充已冻结测验的独立提交 |
| `review_events` | 状态转移前后值、触发 attempt、规则版本、有效复习窗口；不可用覆盖历史的方式“改分” |
| `jobs`、`audit_events` | OCR/分析/生成任务状态、重试次数、失败原因；重要写操作、权限检查与配置变更留痕 |

设计要求：

1. 学习/测试/练习事件分开；只有符合规则的有效独立评测才能晋阶。
2. 同一测验项只接受一个最终提交结果；重传同一幂等键返回原结果，不能重复推进阶段。
3. 业务事务同时完成“写答题事件、写复习事件、改调度状态”；以状态版本/乐观锁防止多标签页并发重复晋阶。
4. 调度以学习者时区计算自然日，再转 UTC 保存；不要仅存无时区字符串日期。
5. 答案、题目版本、诊断可追溯；人工纠正错误判分时，产生修订事件并按规则重算受影响状态。
6. 掌握度第一版展示阶段、证据数、近期独立正确率及样本数；不要把少量题目映射为伪精确概率。

### 5.1 卡片唯一性与后台作业（R2 新增）

- `review_cards` 以 `(learner_id, knowledge_point_id, review_objective_id)` 唯一；同考点的不同训练目标可分卡，同一目标的多道错题/变式只关联同一张卡。知识点只能选择当前课程目录中的有效 ID，模型不能随意新增同义标签制造重复卡。
- v1 每个测验项仅指定一个主要调度目标；综合题的其他考点仅作参考标签，不用一道题自动晋升多张卡。
- 为避免多个标签页并发，一张卡同时只有一个可用于调度的活跃测验项。服务在短事务中预留 `cycle_id`、卡片 revision 和题目版本；取消/过期释放预留，最终提交或人工裁决至多应用一次。
- 幂等键绑定操作、身份、资源和规范化请求哈希；同键不同负载返回冲突。卡片 revision 已改变的迟到提交不得覆盖新状态，可保留为不参与调度的练习记录。
- API 和独立 worker 均可访问同机学习库，但只做短写事务；外部模型/OCR调用和等待用户输入必须发生在事务外。SQLite WAL 仍只允许同一时刻一个写入者，不能当作无限并发机制。
- 作业记录包含 `queued/running/succeeded/failed/cancelled`、租约期限、worker 标识、尝试次数、输入资源版本和幂等键；使用条件更新原子领取。租约过期可重领，但旧 worker 不得提交过期结果。
- 默认最多 2 次可配置自动重试；按“可能重复执行”设计，结果落库去重。超时后外部提供商是否已计费可能未知，不能承诺调用或费用恰好一次。
- 学生原始提交先持久化为 `pending`，判分在事务外运行；最终成绩、复习事件与卡片状态在同一短事务应用。没有最终可信结果前，不能在界面显示“已通过并晋阶”。
- 人工改分产生补偿事件；重放从受影响事件按固定顺序、冻结规则版本重算该卡，期间冻结其新提交。未实现并验证重放前，不开放可以改历史成绩的管理功能。

### 5.2 资料生命周期（R2 新增）

- 审核共享题与学生私有附件明确区分；诊断、导出、附件和日志继承所属学习者授权。
- P0 确认原图、转写、模型请求日志及备份的保留期限；默认日志不收集原始题图或完整对话。先提供经过授权的资料导出和软删除，再按策略物理清理，不能默认为永久保存。
- 删除账号先停用外部身份绑定，保留/清理学习者数据按实际授权决定；不同学生不得因为曾共用监护人账号而连带删除。
- 备份按既定保留期到期清理，不能宣称软删除即清除了所有备份；从旧快照恢复时要按受保护的删除记录重新应用已经执行的删除，避免恢复后数据重新出现。
- 审计最小化，只保留完成追溯所需的标识、操作和结果；不得以“审计不可变”为由永远保存学生原文或密钥。

## 6. 复习调度：先确定、再自适应

### 6.1 首期明确选择“相邻复习的间隔”

建议规则版本 `interval-v1` 使用 **1、2、4、7、15、30 天**作为相邻有效复习之间的默认间隔，而不是累计第几天。阶段 `review_stage=0..5` 对应下一次间隔索引，完整走完后进入 `maintenance`，记录保留。

例如 2026-11-02 完成首次学习并建卡，且每次恰好到期独立答对：

| 动作 | 下一次间隔 | 下一次到期日 |
| --- | --- | --- |
| 11 月 2 日建卡 | 1 天 | 11 月 3 日 |
| 11 月 3 日通过 | 2 天 | 11 月 5 日 |
| 11 月 5 日通过 | 4 天 | 11 月 9 日 |
| 11 月 9 日通过 | 7 天 | 11 月 16 日 |
| 11 月 16 日通过 | 15 天 | 12 月 1 日 |
| 12 月 1 日通过 | 30 天 | 12 月 31 日 |
| 12 月 31 日通过且满足维护门槛 | 进入维护；默认 30 天 | 2027 年 1 月 30 日 |

到期日晚复习时，以**实际有效复习日**计算下一次间隔，保留原到期日和逾期天数作统计；禁止一次补做自动跳过多个阶段。提前练习保留记录，但不自动推进到期复习阶段。该表是可解释的初始产品规则，不宣称等同 FSRS 或经过本项目验证的最优学习日程。

### 6.2 反馈规则

| 结果 | 处理 |
| --- | --- |
| 到期、无提示、独立正确、判分可信 | 按规则晋一阶；每个 `cycle_id` 至多应用一次调度结果 |
| 提示后 / 看过答案后 / 辅助情况不明 | 记为辅助或未验证练习；不晋阶、不据此清零，原阶段保留，次日安排无提示复测 |
| 到期、可信独立答错 | v1 仅把该测验主要目标卡设为 `relearning`、stage 0，次日复习；其他目标和历史证据不清零 |
| 仅模型判断为“概念错误”或“笔误” | 保存错因建议，不直接控制调度；按错因细分升降级须另行验证并发布规则版本 |
| 题目歧义、OCR 不确定、模型判分冲突 | 该测验项 `needs_review`，阶段/原到期时间保持不变；待复核或作废并换验证题，不计失败 |
| U1 外部试卷/作业导入结果 | 作为来源明确的观察与错题材料，不直接晋阶、清零或补跑历史复习；已有卡关联来源，新目标确认后按首次建卡规则安排 |
| 同题重复提交 / 网络重试 | 幂等返回；不新增错误次数、不重复晋阶 |
| stage 5 到期通过且达到跨天、变式与间隔门槛 | 进入 `maintenance`，默认每 30 天复查；可信独立答错仅此卡回到再学习 |

“错因推断不确定”和“对错判定不确定”分开处理；前者不妨碍保存可信成绩，后者阻断调度。v1 先采用上述确定规则，避免自动错误标签驱动状态变化。

### 6.3 今日任务与掌握证据

- 队列同时包含新学项目复习和错题目标；按逾期程度、再学习需求、近期独立失败、知识点覆盖和预计耗时排序。
- 每日有时间/数量上限；积压时优先旧任务、限制新卡，显示未完成数量，不悄悄推迟并隐藏积压。
- 同知识点和近似题限制集中重复，避免同一个答案记忆造成多次“成功”。
- 维护准入同时要求：当前为 stage 5 的到期测验、至少 3 个不同自然日无提示通过、至少 2 种已审核变式，并且本次距系统内该目标最近学习/提示/练习暴露至少 30 个自然日。即使 stage 5 答对，若最近用过提示而间隔不足，仍保留 stage 5 并安排 30 天后再测。
- 图表标注“辅助完成”“独立通过”“待复核”和样本数；样本不足显示“证据不足”。

### 6.4 v1 执行语义（R2 新增）

- 新卡为 `review`、stage 0；默认学习者时区 `Asia/Shanghai`、到期时刻本地 08:00。间隔以可信结果被接收的本地自然日加天数，映射成明确 UTC 时刻保存；用户更改时区不追溯改写已保存到期时间，新的调度使用新时区并记版本。
- stage 0..4 到期有效通过后，`next_stage = stage + 1`，下一间隔取 `[1,2,4,7,15,30][next_stage]`。stage 5 通过走维护门槛，未达门槛仍 stage 5 并等 30 天。维护期通过仍间隔 30 天；不据此宣称永久掌握。
- `relearning` 卡通过有效独立测验后按同一阶段规则返回 `review`；失败继续为 `relearning`。评估维护门槛时先读取当前事件之前的最近暴露时间，再写入本次作答/反馈事件，避免将本次作答算成间隔为零。
- 可调度提交需有未消费的预留、匹配 revision、未过期挑战、可信原始作答、最终判分和可核实的辅助状态。任何一项不满足均不晋阶；“打开任务列表”不消费窗口。
- 提前练习只写练习及暴露记录，不提前推进或顺延到期日。辅助的到期测验不推进阶段但产生下一日复测周期；同日重复题不计新的跨日掌握证据。
- 取消或断线不等于答错；保留服务端会话以便鉴权后恢复。过期的离线提交按练习草稿处理，不接受客户端任意回填时间改变调度。
- 待复核项若需要换题，应先使其原调度资格失效再释放预留；其后复核结果可修订历史，但不能与替代测验分别晋阶。
- 每次提交根据 `cycle_id + revision` 原子应用一次；生成下一个周期不允许本周期的迟到回调再次生效。
- “独立”仅表示系统内已验证输入且未观察到辅助，不是监考或作弊识别。普通聊天转录、历史解析上下文中的同题复述和辅助情况不明的作答不得自动计作独立掌握。

### 6.5 FSRS 的后续位置

FSRS 适合在有明确复习对象、评分语义和有效日志后评估；其目标保持率与复习负担有关，不能仅用“间隔翻倍”代替。后续先用于概念、公式、词汇等相对稳定的记忆卡，在相同日志上做影子计算，再小范围启用。综合数学题的变式难度、提示依赖和迁移表现仍需单独建模，不能把答题正确率直接当作记忆保持率。

第一版保存 `scheduler_version` 与原始事件，为以后切换算法保留条件；当前不承诺用少量日志拟合可靠的个人遗忘曲线。

## 7. 归因、变式与判分质量

### 7.1 归因输出约定

诊断输出包括：`knowledge_point_ids`、`error_types[]`、`evidence_steps[]`、`hypotheses[]`、`needs_clarification`、`remedy_notes`、`diagnosis_status`。置信度标签仅用于复核路由，不能当作经过校准的概率。

- 错因类别可多选：概念、条件理解、方法/公式、运算/书写；另有“信息不足”“题目/OCR 问题”。
- 区分学生原话、可观察错误和模型推断；缺少步骤时先请求关键步骤。
- 讲解用“这一步遗漏了条件”，不用“你就是粗心/顽固”等人格或负面标签。
- 诊断可以被学生或监护人纠正，保留版本；如果依赖的标准答案尚未验证，则诊断也不直接发布为最终结论。

### 7.2 教学模式与测验模式

**教学模式**：错因回顾 → 分级提示 → 练习 → 解释。允许错因唤醒，记录辅助程度。  
**独立测验**：只展示题目 → 收集答案与必要步骤 → 可信判分 → 再给针对性解释。测前不提示该题的关键陷阱。

正式测验的交互中先收取原始作答，再将反馈返回给教学模型；题目、评分依据和学生答案不得在作答前通过历史聊天、RAG片段或工具结果自动合并泄露。若无法隔离当前对话中的提示/答案，切换到无解析的可信测验交互；无法判断则标记 `assistance=unknown` 并只作练习。系统不能据此证明学生未从外部获得帮助。

活动测验期间，服务对关联目标的诊断/解析查询设门禁：拒绝返回，或先把本次标为辅助再返回，不能仅靠提示词要求模型不调用。判分服务的答案端点不注册为学生工具，其他学习入口对该目标的系统内暴露也写入证据记录。

有提示的尝试不会被浪费，仍作为教学事件保存；只是不能与独立测验混为同一掌握证据。

### 7.3 变式和判分流水线

1. 从知识点、已审核母题、课程范围和目标难度生成候选题。
2. 校验题目完整性、可解性、答案/定义域、目标考点、课程边界和与原题的差异。
3. 对简单数值题/方程使用程序或符号校验；几何证明、开放题采用明确评分量表并设置复核条件。
4. 两次模型回答一致仍不等于数学证明；第二模型复核只能作补充，不能替代确定性验证或人工审查。
5. 通过后冻结题目与答案版本；草稿、待校验题不能投放到正式测验。
6. 只在服务端使用标准答案判分；输出可解释步骤反馈。答案争议进入复核，不影响调度。
7. 保存题目生成、验证、判分版本和耗时，便于复现问题。

首期最好采用“审核母题 + 受约束变式 + 程序校验”，逐步开放生成范围。换数字也要检查是否改变题目性质，不能认为只换数字就天然安全。

## 8. 拟议工具接口与确定性交互

模型可见工具与服务内部命令分开发布。OpenAPI 契约中的端点不自动全部变成 LLM 工具；工具发现使用允许清单。

| 操作 | 模型可见性 | 服务端边界 |
| --- | --- | --- |
| `record_learning_event`、`add_wrong_question` | 允许提交候选输入 | 默认形成待确认记录；模型转述不能直接当学生真实打卡或答案 |
| `request_document_analysis`、`get_import_status`、`list_import_candidates` | U1 允许清单工具 | 仅分析/查询已授权附件；长任务返回 job ID；模型不能指定任意抓取 URL/文件路径，候选答案受测验暴露门禁限制 |
| `get_diagnosis`、`request_diagnosis` | 可见 | 已授权题目方可分析；长任务返回 job ID；额度/并发由服务限制 |
| `get_daily_review_tasks`、`get_learning_progress` | 可见，只读 | 强制学习者授权过滤；查询不创建复习事件 |
| `start_test`、`confirm_draft_interactively` | 可见的交互编排工具 | 适配器启动挑战并读取原生 UI 回调；参数不接受模型传入 `confirmed` 或最终学生答案 |
| `request_hint`、`request_grade_review` | 可见 | 仅请求提示/复核；提示由服务记录；请求复核不等于批准改分 |
| `confirm_learning_event`、`confirm_question_draft`、`submit_answer` | **不暴露给模型** | 学习打卡、题目转写和答案分别有操作绑定的挑战；只允许受信 UI/适配器消费后调用，保存原始输入，禁止调用方传 `is_correct` |
| `confirm_import_batch` | **U1 不暴露给模型** | 批次、选中题目与各 revision 绑定一次性挑战，可信 UI 批量确认；重复调用幂等，旧版本/越权拒绝，逐项返回实际入库结果 |
| 授权变更、题目审批、复核裁决、事件重放、数据导出/删除 | **管理接口，不暴露给模型** | 独立角色校验、操作确认及审计；服务凭据不替代最终用户权限 |

所有变更均有幂等键和版本条件；同键同请求返回原结果，同键不同负载拒绝为冲突。模型负责解释与发起允许的工作流，服务和可信交互负责事实输入。不能仅通过 system prompt 来限制敏感工具的调用。

## 9. 实施计划与验收门槛

估算前提：1 名开发者负责实现，用户或熟悉学科内容的人提供样题及验收；P0 证实模型连接和原生交互可用，不包含大规模教材清洗、模型训练、独立移动端或后备答题网站。以验收门槛推进，工作日仅为范围估计。下表数值保留为 R2 原基础闭环估算，其中已包含升级演练与兼容回归；U1 整卷上传及多模态增量尚未计入，不能当作当前完整范围的总工期。

| 阶段 | 预计工作量 | 交付物 | 必须通过的验收 |
| --- | --- | --- | --- |
| P0 基线与可信交互验证 | 2~3 人日 | 固定镜像、备份恢复、凭证整改、导入修复、课程样例与真实模型/交互探针 | 旧版恢复成功；可信输入/取消/超时/断线/重放/身份切换均符合约定；失败教材定位；选定章节抽检 |
| P1 数据与调度 | 3~5 人日 | FastAPI、迁移、稳定身份映射、学习者授权、事件与 interval-v1、作业租约 | 时区、维护、提示后复测、重复/并发、过期回调、worker崩溃、跨学生越权通过 |
| P2 诊断与受约束出题 | 3~5 人日 | 结构化归因、审核母题、变式校验、可信判分、复核和结果版本 | 不合格题阻断；未知答案不自动判对；模型失败不推进；改分重算按规则 |
| P3 接入及升级回归 | 3~4 人日 | 薄 Tools、学习教练、可信答题、今日任务、演练环境、配置对账和兼容矩阵 | 完整闭环通过；副本启动无正式副作用；旧版恢复；UI只读检查之外的真实回归证据 |
| P4 小规模真实试用 | 1~2 人日开发修订 + 7~14 天观察 | 问题清单、任务预算调整、抽查判分记录、使用说明 | 样本中的调度一致性和幂等性通过；无跨学生数据混用；题目质量达标；持续观察任务完成和误判情况 |
| P5 增强版 | 按试点结果再估算 | 复杂手写/几何识别、经批准的自动入库策略、提醒、热力图/成长趋势、其他年级学科、FSRS 影子评估 | 每项有独立质量基线，不因加功能破坏原闭环；基本整卷导入不再推迟到本阶段 |

**R2 开发试用版估算 11~17 人日；含试点修订共 12~19 人日，另需 7~14 天真实使用观察。** 原 8~12 人日未完整计入可信交互、作业恢复和升级演练，已被本估算替代。这不是工期承诺；P0 完成后按实测重估。原生交互失败、需要独立页面或无法安排学科审查时，依赖项暂停并重新确定范围。

**U1 范围调整**：完整产品试用增加 U0 样本/附件验证、U1 上传分题、U2 判错与批量入库、U3 归因复习回归四项门槛。U0 与 P0 对齐，U1 复用 P1，U2 接 P2/P3，U3 在 P4 真实试用前完成；具体任务见 `PAPER_HOMEWORK_IMPORT_DESIGN.md`。需要在 U0 实测后重新合并估算，原 11~17 人日不能表述为已经覆盖本模块；共享工作不重复相加。

**阶段门槛**：G0 为身份与真实输入链路、恢复和模型可用性；G1 为状态机、幂等和并发；G2 为题目与判分质量；G3 为完整闭环和升级回归；G4 为真实试点验收。文档已修订不等于任何门槛已通过。G0 未通过时，可以做独立单元开发，但不得宣布依赖交互的正式测验上线。

### 9.1 必须实际执行的测试

- **调度**：上表日期可复现；跨午夜/时区、迟到复习、离线后补交、连续失败、辅助答对、维护复查符合定义。
- **幂等与并发**：重复网络请求、模型重复工具调用、多标签页提交都不能多记成功/失败或多次晋阶。
- **隔离**：至少两个测试学习者，覆盖查题、统计、导出、附件、复核等越权路径；前端隐藏不算授权。
- **答案隔离**：检查工具 JSON、前端网络响应、流式事件和错误信息，测前都不出现答案与解析。
- **故障**：模型超时、非法 JSON、服务重启、磁盘/数据库写入失败后不出现半完成的有效成绩。
- **可信交互**：用非空错误对象、`None`、取消、错误账号、过期/重复挑战、相同键不同负载、模型伪造“已确认”等测试输入验证拒绝路径；没有真实回调不能提交最终答案。
- **维护状态**：使用可控测试时钟验证 2026-11-02 至 12-31 的六次复习、2027-01-30 的维护复查，以及 stage 5 前一天获取提示后不能立即进入维护。模拟时钟测试只能验证规则实现，不证明真实学习效果。
- **作业与改分**：重复领取、租约过期、旧 worker 迟到结果、提交已保存但判分未完成、人工改分后事件重放；阶段只按有效结果变化一次。
- **质量基线**：建议准备约 30 道带教师/人工参考判定的样题，覆盖正确、典型错因、缺步骤、歧义、公式/OCR和提示场景；另审核约 20 道投放变式。样本数量是试点设计值。
- **整卷导入（U1）**：多题/跨页/批注/部分得分/缺页/答案错版、重复上传、版本变更后确认、后台取消与恢复必须覆盖；按全部标注题报告错题召回、误判和待复核比例。单题质量集不替代整卷验收，导入成绩不应改变已有阶段。
- **首期发布门槛**：上述业务与权限用例全部通过；抽检投放题无已知无解/答案错误/超纲问题；未达标题型禁投并留在练习或人工复核流程中。有限样本通过不代表全部题目准确。
- **学习效果观察**：区分独立正确率、辅助完成率、重复错因率、逾期率、实际用时及样本量。7~14 天只能评估可用性与初步趋势，30 天间隔及长期保持需要更长观察。

### 9.2 部署与回退

升级兼容与数据库恢复以同目录 `UPGRADE_COMPATIBILITY_AND_RECOVERY.md` 为补充约束：学习业务独立，接口版本化；候选版本先用隔离副本演练，正式切换重新备份；数据库迁移后不能仅回退镜像。该文档还明确持久化配置来源、原生工具内部依赖和开放写入后的增量保护。

- 第一阶段在现有项目内新增学习服务、适配器、测试和文档；不要创建另一套无关项目。
- 新服务先以独立 Compose 服务和数据目录接入内部网络，默认不向公网暴露业务端口；后台 worker 独立于聊天请求。
- 现有 Open WebUI 固定 digest 后增加工具/模型配置；不编辑运行容器里的源码，不写入内部业务表。
- 使用 SQLite backup API 或维护窗口做一致性备份，不能只复制正在写入的 `webui.db` 而忽略 WAL；学习库、附件、向量索引和配置需有匹配快照。
- 新学习服务首次发布失败时可禁用其工具并停止该新服务；后续仅升级 WebUI 时按升级文档选择最小回退范围，保留兼容且正常的学习服务及新增事件。数据库迁移优先向前修复，需要回滚时使用经验证的匹配备份并核对身份关联。
- 文档、代码纳入版本管理，数据和凭证排除。验收后记录运行版本、配置版本、已知限制、备份时间和恢复步骤。

首次建立隔离演练环境、兼容回归与配置对账已计入 R2 的 P0/P3，不再额外叠加 2~3 人日。常规升级耗时在完成首次演练后再评估；软件升级不与新业务功能或密钥轮换捆绑发布。
